## 运行操作

1. `CDUT 专区 → 材料审核 → 新建审核项目 → 勾选 D4 技术预审`。
2. “系统选择文件”通过操作系统原生文件对话框选择同一申请事项的 1–8 份材料（单份 50MB、总体 100MB）。Main 将授权文件复制到 OS 临时私有目录，生成仅本窗口可用的、不含路径的随机短期令牌，20 分钟过期；取消选择不改变现有选择。“拖入”可触发原生选择器，但**不直接信任拖来的路径**，必须由用户在系统框中再次授权。
3. 原 Main 只对已固定的候选目录按有限关键词或文件名中的候选 ID 进行可解释匹配；纯文本只读前 16 KiB。PDF/Office/图片未通过解析得到的正文不作为自动路由依据。信号明确且唯一才显示“20 秒后采用推荐”；材料混合两个明确事项则拒绝合批；低置信度提示人工选模板。
4. 20 秒倒计时只将推荐项选到已有 D4 模板下拉框；用户任意时刻手动选模板即取消自动覆盖，也可点击“立即采用”。**不得因此自动建立案卷、设定业务对象条件、确认申请人、生成 Gold 或触发 Pi。**
5. 沿 P1-A/B 真实对象和三态表单逐对象填写、人工确认后才允许建案。Main 校验模板、来源、对象和 `reviewerConfirmation`，再校验 token 属于当前窗口、未过期、未被消费、不含明显多任务，之后沿既有 D2 固定 Plan 建案。
6. 建案成功后 **Main** 顺次通过已有 `case-import.importDocumentFromPath` 正式拷贝/解析暂存原件到该案卷 `application` 栏（这是 Main 自己从系统选择器获得的受控路径，不是原 `IMPORT_DOCUMENT_FROM_PATH` 开发 IPC）。上传不能替代 EvidenceLink 逐对象来源确认；开始 Pi 前须检查材料和责任关联。
7. 某材料解析失败时返回真实案卷及临时 `d4IntakeFailures`，GUI 显示错误；不得将此记为材料解析通过。永久 Plan 仍为 candidate-held、technical-pre-review，不接受行政审批授权。

## 明确技术边界

- Main 源码：`review-d4-intake.ts`（OS picker、临时副本、token/owner/TTL）和 `review-d4-routing.ts`（可测的保守推荐）；`review-d4-client.ts`（固定 D2 建案后导入）；`review-ipc.ts`/preload 只暴露系统选择/丢弃，不暴露文件路径；表单维持 P1-A/B 原合同。
- **词表本轮先覆盖两套实机验证过的候选** `g03-t01`、`g08-t02`，以及 50 候选的精确技术 ID；其余候选可由用户手选。不得把这写成“50 套语义自动匹配已完成”。词表用于安全可解释的技术选择，不得被当作校规事实。
- 若用户提前关闭对话框，尝试丢弃当前暂存；进程崩溃时临时目录可能留下文件，见下方清理遗留问题。内部 Map 不跨 Main 重启；旧令牌不可恢复。
- 依照冻结 Plan 合同，**改变模板或条件需要创建新案**；导入材料不重新编译旧 Plan。
- 模板推荐发生在用户明确点击新建案卷后的 D4 入口，并非整个 CDUT Studio 的全局拖入自动识别。
- 不迁移 P06 Main-owned Pi 背景 owner，不扩张 Pi 工具权限。

## 需记录的实际缺口和下一步

1. 此轮不是 50 领域的自动路由分类器；建议词表可逐领域补充，先积累错推/漏推反例。
2. Native dialog 授权前拖入不是直接读取；正式版从拖入文件获取 OS 授权的安全可靠实现另行评估。
3. 暂存目录进程崩溃后需要有界、可验证的启动清理机制；不能随意删系统其他目录。
4. 创建案卷之后如果发生不可恢复错误，可能留下需要人工补材料的 partial case；需保留 caseId 提示并独立追踪，而非静默重试建案。
5. 若 CI 和实机都通过，再冻结 P1-C SHA 转入 P2（提示词/工具提交开销优化）。
