# 06｜历史需求、现实缺口与少量 V3 机会
**缺少证据不代表能力完全不存在；以下区分设计目标、已有局部代码与未形成产品验收。**

## 已在 02/04/06/07 目标规范明确但未证实完整达成
1. **模板从自然语言到发布（F02/F03）**：D0.5/D1/D3 作者工具很强，用户仍需完整无代码创建第七业务、冲突确认、试跑、复制/导出并验证发布，不应将 JSON CLI 当产品完成。
2. **A03/A04 批量分案与多模态归属**：D4 W1 有原生选择器、文件角色、hash、批次导入，但 100 案/500 文件、坏件、错名、多 Subject、完整图片/Excel 定位的独立 GUI 验收未做。
3. **真实可靠的单案全覆盖**：D2/Pi、ledger、D4 prompt 修补有代码，旧漏项回归和 Provider 真实 tool receipts 缺少跨模型质量闭环；自动技术流程仍不能认定完成 A08/A16/A18。
4. **完整模版原文业务无损性**：D3-MD-Q1 只可找部分缺口；G01–G08 合成编译不代表真实政策可用或全部 C 规则无损。
5. **可靠运行/恢复与长任务**：P06 的 Main owner、工具最小授权、多批 Run 归属已实现部分，但正常重启≠故障卷跨 PID，真实 stop/abort 与重复启动跨模式仍需验收。
6. **角色、多评委、审批组织者体验**：V2 Judging/OfflineRoundtrip 有核心业务模型；独立多副本、保密状态、评委邀请、超时与真实校方身份仍缺端到端。
7. **报告、出站和学校接口（F16/F18/C/S）**：现有 report/offline/SchoolPort 候选不能证明学校业务系统已经接入；需具名实际回执、幂等、冲突和断网复盘。
8. **真实模型能力诊断和预算**：模型可用性、OCR/vision/tool calling 能力应在不同会话和运行中可见；不得因缺通道回退假成功。

## 仅建议评估、不是本轮新增设计决策
- **差分解释与影响预览**：改事实、材料、政策或模板前，用 Check/Subject/Run 映射展示哪些旧结论失效，帮助审核员减少重复劳动；已有 D3 upgrade impact 和 V2 input invalidation，可对齐而不是另造引擎。
- **实验回归索引**：把“source/原图/Gold ACL/固定 SHA/失败首因/测试层次/业务认可”做机器可追溯独立证据卡。来自大量 E/MDQ1/P06 实验的共性痛点。
- **审核性能剖面（非自动授权）**：按案卷记录模型实际成本、材料页数、未覆盖原因和人工更正量，选择性优化长文档阅读；不能用 token 数替代正确率。

**不建议新增**第二套单案审核引擎、用户必学复杂规则 DSL、依赖模型置信度的自动审批、按校名复制整套模板的重复业务树。这些看似能力新增，实际上加重维护与安全成本。
