## 3. 跨 G05 模块复用策略

- **共用 S0：政策版本/适用性定位**（本地共性局部模块候选）：school/project/year/batch/actor/stage；来源分级、`POLICY_UNKNOWN`、不跨校套政策。可按同一技术形态在六套分别绑定**各自来源**；不要冻结一个虚构的“全校统一外事审批政策”。
- **现成 B01 `agent-authorization@1`**：仅在授权人、经办人、可代办事项、委托范围和有效期这一局部责任确有等价时复用；例 T02 R-14/R-44、T03 R-32、T04 R-02/R-42、T05 R-04/R-11、T06 R-02/R-03/R-20。T01 是否存在相同委托责任须在源 R 级确认，未确认可**不引用**。授权成立**不等于**申请人资格/学校审批/来访准入。
- **现成 B02 `evidence-source-boundary@1`**：可用于来源定位、材料版本、可信度和待确认边界；如 T01 R-46/R-47、T02 R-33～35/R-43/R-45、T03 R-28/R-33/R-35、T04 R-33～36/R-47～48、T05 R-31/R-35/R-36、T06 R-39～41/R-48。该共享试验资产不是校方政策签署，也不提供复杂 Claim 图。
- **建议新建但先保持 workspace-local**：证据替代与材料时点、活动/团组名单一致性、费用合计与分担、外事/推荐/办会有权事件状态、变更与旧批件范围、风险人审转办。多个业务只可共享“局部对象和解释完全相同”的核对行为；不得为了共享而合并不同审批目的。是否冻结为新的公共模块留待 D4 使用证据，**不以新增模块数考核进度**。

## 5. 具体公共 GAP、受影响责任、最小补充与复验关闭线

### G05-G01｜缺少**通用业务对象与逐实例 Check/Subject 绑定**（ENGINE / BLOCKER FOR FULL_EQUIVALENCE）

- **事实/复现**：R1 `review-d2-runtime.ts:validateTargets` 对 G05 `kind:'activity-member'` / `'expense-line'` / `'visitor'` / `'approval-step'` 等均走未知目标的 `D2_TARGET_INVALID`；采用现有 `student-field` 会被 studentId/fieldKey/intents 校验阻断；采用 campus-card 则一分支单目标限制，擅自换成 archive-operation 是业务语义伪装。档案专用 `review-d3-dynamic-case.ts` 不能直接套 G05。
- **涉及**：T01 受益人/每费用 R-03～06/R-27～33/R-48；T02 R-07～12/R-17～25/R-30/R-39；T03 R-03/R-16～17/R-21/R-36～42；T04 R-09/R-17/R-37/R-39/R-45～46；T05 R-07～12/R-32；T06 R-17/R-21/R-43/R-46～47（其他同组实例责任亦受影响）。
- **受损语义**：同案多人/多行明细/多外部机构有不同证据、状态和结论；现在只报一个整案 Check 会隐去部分失败，可能产生一证覆盖不相关对象的风险。
- **最小补充**：一个**通用显式业务 target**（稳定 objectKey、subjectId、对象类别与父/关联对象键，不预设 G05 专门类型），允许同一模板多 target；让 task 或 `sourceBinding` 实例化并精确绑定 checkId→objectKey→subjectId；对未登记对象、未使用目标、重复/越界绑定 fail-closed。保留现有 archive/card/student 严格校验及兼容计划；新增相应固定计划映射及 Pi 回执逐对象检查。**不要求先造任意角色图、数据库或新审核 Agent**。
- **关闭试验**：同一 T02 活动两名成员只有一人有保单，不得输出团队“全员保险通过”；T01 两个费用行仅其中一行满足额度，不得共享“全部合格”；T05 两访客仅一人有专项许可，不得互相借权。两条真实 Rule/Subject/SourceRef 及变更版本单独存在，非法对象被拒。

### G05-G02｜**业务阶段、有权审批事件与证据提供者不可无损执行**（ENGINE + AUTHORITY-CONTRACT / BLOCKER FOR FULL_EQUIVALENCE）

- **事实/复现**：`D2ExecutionGateV1` 的 `case-stage`、`material.dueStages` 只理解固定技术 `CaseStage`，不是 T01～T06 各自 ST-xx（会前/校内推荐/财务/上级批准/行前/会后等）；`authority` 提供者虽然会阻止由 AI/申请人断言 compliant，却没有独立的受控**有权批准/否决/撤回**事件输入与动作范围验证。单一个整案 stage 会让不同节点串用。
- **涉及**：T01 R-34～44；T02 R-26～32/R-36～41；T03 R-06/17/21～23/29～36/41～43；T04 R-13～17/21/25～32/41～43/46～48；T05 R-09～11/29～34/37；T06 R-08～12/25～35/39/42。
- **最小补充**：在固定案卷计划里显式登记**本模板业务 stage ID**（不强改通用 `CaseStage`）及授权部门/节点和目标对象的受控**事件声明**；事件至少含状态、来源系统或人工受控确认者、适用对象、发生时间、原签发版本、失效/撤回版本。校验时区分“上传了批文影印件/提交回执”和“经有权渠道确认该审批事件”；没有可信输入时**待确认**而不是臆造批准。所有当前 D2 行政禁止自动签发门禁继续有效。允许首轮仅做只读/手工确认的受控事件接口，不要求直接接真实 OA。
- **关闭试验**：T03 只获学校推荐未获外方录取，保留前者状态，后者待确认；T06 年度计划已收录、上级办会审批未签发，不得给准许举办；T04 正式拒批后新增材料不能推翻有效否决；T01 会前不得因缺会后履约材料判申请人缺件。

### G05-G03｜**原文复合证据的逐对象 AND/OR/版本/条件约束未全映射**（ENGINE / SCOPED GAP）

- **事实/复现**：当前 `review-d2-execution-gates.ts` 支持有限 `evidence-any` 和布尔门禁，但前者需要关联具体 subjectId/current document；完整作者态 `advanced.evidenceRelations` 非空编译直接 `D2_UNMAPPED_ADVANCED`；仅写“满足任意合法证明”到 RuleSpec 文本不等于程序已证明替代材料与申请人、阶段、发证者、旧文书范围一致。无通用的多对象动态分支选择，T06“会议中的参与者集合按身份过滤计数”也无保证。
- **涉及**：T01 R-13～20/27～33/38～41；T02 R-21～25/29～32/43～45；T03 R-08～15/24/28/37～40；T04 R-09～10/17～22/27～31/40/45～48；T05 R-07～12/17～24/28～29；T06 R-14～21/30～35/43～49。
