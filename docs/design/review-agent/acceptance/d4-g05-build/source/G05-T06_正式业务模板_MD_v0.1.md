## 1. 模板元信息、审核目的、适用及排除范围

**独立审核目的**：有权校内单位申请以学校、学院、科研机构名义申办、主办、合办、承办或组织国际学术会议，在其合法有效的政策范围内完成**年度计划、对外竞逐承办权、正式举办申报、主管部门审批、获批后的组织与重大变更、会后成果归档**的不同阶段审查。把「申办权」「承办权」「学校正式办会批准」「上级正式批复」「批准范围内对外通知」「会议已真实举行」「归档完成」作为彼此不同的事实与权利。[L01][L02][L10][L13]

**适用**：学校认可的学院/职能部门/科研平台作为根申请主体；老师或学生只有明确授权才能代表组织提交。一个会议可有多个主办/承办/协办组织，但只生成一个有确定主体的会议举办申请根对象；其余角色按组织关系存档。线上、线下、混合、社科、理工、重大会议、双边或多国、受托承办等属于**条件轴**，不自动拆为新模板。

**排除与跨模板引用**：`G05-T01`个人参会专项资助、`G05-T03`校际交流选派、`G05-T04`师生个人出国境任务、`G05-T05`单人外籍专家来访与证照，以及`G07/T04`会议费/酒店报销、教学课程开设与校园场地预约，均为相邻业务。引用对应决定可以为当前会议提供证据，但不互相覆盖批准范围。[L01][L02][L12]

**权威政策原则**：只有确定本校现行版本及适用期间才能执行必须提交/时限/分类/特定机关的强制性规则。`L01`列有“下一年度10月底预报、重大6个月、其他3个月、会后一个月”；`L02`明确“国际处审核备案→分管外事校领导审批”与专业归口。二者未有权威现行衔接解释，前一组时间参数**仅候选可配置项**，不是v0.1自动驳回门槛。`L02`提到的1000人属于一般学术会议的专业归口阈值，不可用它代替国际会议外事审批。[L01][L02]

## 2. 一套模板的独立业务根对象与最小审核单元

- `conference_case_id`：会议主案件，会议正式ID、届次、申办单位、政策profile。不能仅靠会议简称把不同年份的会议合并。
- `action_id`：**一个可独立批准/拒绝的申请动作**，类型为`PLAN_PREVIEW`、`BID_FOR_HOSTING`、`APPLY_HOSTING`、`CHANGE_SCOPE`、`CANCEL_HOSTING`、`POST_MEETING_ARCHIVE`或`PUBLICATION_REQUEST`；每个动作有自己的申请阶段和审核结果。
- `entity_role_id`：主办/共同主办/承办/协办/外方机构/学术负责人/经办人/主管机关的一条可审组织关系；经费赞助关系不自动转成主办。
- `guest_action_id`：涉特殊嘉宾邀请、实体来华等逐人动作。若可从会议本体批件范围**合法分离**，可独立待批；若上级明确要求会议整体重审，须把阻断范围升级至会议动作。[L01][L02]
- `approval_event_id`：某有权机关就某明确对象、动作、时间和地点作出的历史决定，不能由模型创建真实事件，只能读取、核验并引用。
- `archive_action_id`：会议实绩和成果归档，未举办则没有该动作的结果；财务核销另案。

最小单元：`(case_id,action_id,review_object_id,stage_code,rule_id,policy_profile_id)`；单案多动作、多人及多组织允许分别输出`PASS_FORMAL_FOR_STAGE`、`AUTHORITY_PENDING`、`OFFICIAL_REJECTED`等状态。根案件不因一个嘉宾未获批而自动改写全体已有许可。

**条件求值契约**：每个布尔条件采用`TRUE/FALSE/UNKNOWN/CONFLICT`四态；互斥枚举字段缺失为`UNKNOWN`，互相矛盾为`CONFLICT`。`FALSE`在**条件确认不适用**时返回`NOT_APPLICABLE`，**不是**资格拒绝；`UNKNOWN`必须暂停该分支的决定，保留可以独立审查的其他分支。`CONFLICT`生成证据冲突及关联原页。有权外事机关确认的profile优先于外校经验和未核实旧制；对权威冲突不得按时间新旧自行裁决。

组合示例：`ST-30 + 混合会议 + 社科 + 外方联合主办 + 无校内经费` 同时激活会议正式表、社科/宣传（在本校适用时）、外方委托、分渠道会务方案；不因无校内费用而免会议审核，也不要求线上代表提供来华签证。`ST-20 + 承办权授予 + 重大会议` 只确认取得承办权事实，不产生举办批件。[L02][L08][L10]

## 9. 原子审核规则（R-01—R-49，逐条可追溯）

**默认政策作用域**：每一条规则的作用范围均为`G05-T06`，绑定`policy_profile={school_id,policy_version,effective_dates,stage,meeting_type,role}`；`B来源ID`仅说明研究依据。标注“校本未确认”的时间、双边定义、上级层级和材料必填规则**仅允许生成待政策核验，不允许自动行政拒绝**。规则结果是对`action_id / entity_role_id / guest_action_id / approval_event_id`中的指定对象产生的建议，不更改其它对象既有审批结果。

**规则流程**：先判触发条件`TRUE/FALSE/UNKNOWN/CONFLICT`，只对TRUE逐项验可信证据；若证据不足依本条处理路径，缺件可补与已正式否决严格分开。没有未发生阶段的材料必须在事前存在这一要求。下面列出每条触发、充分事实、缺陷及后续动作；**来源、字段和材料均精确给出**。

### R-01｜POLICY-01：无法确定两种规定是否仍并行时不得作资格拒件

- **审核目标及对象**：整个申请及依赖政策判断；制度profile能定位学校与办理年份；生效阶段：`ALL`。属于`校本直接/待确认`，适用政策版本始终需先通过`R-01`解析。
- **触发条件**：选择制度profile且需运行任何业务规则。条件`FALSE`则本条`NOT_APPLICABLE`；条件`UNKNOWN`则`CONDITION_UNKNOWN`；条件冲突则`DATA_CONFLICT`并引用冲突证据。
- **必要事实和证据**：政策注册表提供学校+生效期间+会议类型+版本冲突裁决。字段：`F-63`；材料：`按对应EV组对应材料/权威数据`；等价证据组：`EV-01`。若等价组条件被满足，不能仅因某个纸件未上传而拒件。
- **可确认时**：存在唯一适用、经权责单位确认的版本→继续评估。这只说明**该规则检查目标**成立，不自动改写会议总体审批状态。

**聚合算法（可复核的建议语义）**：

1. 为每个`action_id`保留所有适用规则的完整结果数组；分项`rule_id`、对象ID、条件值、证据定位、问题码、下一动作分别输出。缺件、冲突、权限待批可以同时存在，不能只展示“最严重的一个”。
2. 先保留权威历史决定：某一对象有`OFFICIAL_REJECTED`的真实决定，不将其写成“未上传材料”；同一范围有正式允许但缺附属嘉宾许可时，保留原会议`APPROVED_PENDING_EXECUTION`与嘉宾项`AUTHORITY_PENDING`两条事实。
3. 若政策未确定或身份/批件无法核实，整个动作不能给“可执行/已批准”；`POLICY_UNKNOWN`、`AUTHORITY_UNVERIFIED`应作为**阻断执行**的待办项，却不等同申请人不合格。
4. 对必须材料缺失、证据冲突、权限待批分别返回`MISSING_REQUIRED`、`DATA_CONFLICT`、`AUTHORITY_PENDING`；可以给其它可独立核验的分项`PASS_FORMAL_FOR_STAGE`，不做“全项一个布尔值”。
5. **许可条件**：`may_publish_or_hold=true`只允许在`APPROVED_AT_STAGE`有真实对应机关决定，且申请动作、人员/地点/会名/时间完全包含在批件有效范围内、所有依法必需的其它审批节点已形成且没有覆盖该范围的正式撤销/否决时由**有权系统**下发。离线模板本身不得把该字段置TRUE；最多输出`execution_gate_recommendation='READY_FOR_AUTHORIZED_VERIFICATION'`。
6. 跨模板的外国嘉宾来访许可、个人会议资助和酒店财务核销使用独立结果槽；失败只阻断其必要的关联动作，除非存在有权机关明确的整体依赖规则。

## 11. 补件、变更、撤回、版本更新与审计生命周期

1. **提交/退补**：每次提交创建版本和SHA-256哈希（源文件仅引用哈希），为`MISSING_REQUIRED`开具体文件/字段补正单，不覆盖旧页证据。
2. **重审**：对已变更的证据/影响字段计算依赖规则集合，只重评其规则并再跑跨规则聚合；保留旧问题、关闭理由与时间，不丢失复核历史。
3. **审批不可模拟**：系统可准备材料、提醒有权人、提取签章图像，但只有合法OA/纸质决定核验才产生`APPROVED_AT_STAGE`及决定ID。
4. **已批范围变更**：重大变更为`ST-60`独立动作，持原批件、旧新比较与新批复；在批准前维持原许可范围，新安排不得以“已提交变更”直接执行。[E03][E04]
5. **撤回/取消**：正式撤回、官方否决、批准后取消均保留原批准事件与对外公告记录，不删除历史；如果涉及已发布通知或合同，生成后续告知与财务/合同待办。
6. **身份授权变化**：经办人职务或单位授权被撤销后，未签发申请动作停止代办，已历史签发文件不被默认为无效，须有权部门判断效力。
7. **政策更新**：按版本生效日重算未办结申请的适用性，不能自动用新法回溯历史会议许可；交叠冲突进入`POLICY_UNKNOWN`并标记需主管处室解释。
8. **执行后归档**：会议结束才触发总结、签到/平台日志、归档号与必要的学术成果。与G07/T04财务核销各自独立；会前无这些文件返回`NOT_APPLICABLE`。[L01][L12]
9. **审计事件**：记录何人何时上传、谁查看何种敏感证明、官方数据查询接口及其故障码、引用的规则版本、报告生成时间、人工覆盖/否决的有权主体，不在输出公开原文隐私数据。

## 12. 合法例外、替代路径与人工限制

- **电子与纸件等价**：可核验OA授权记录、真实电子签章或有权纸件可以替代重复上传的同一事实；合同/邀请函仅证明其签发机构有权承诺的事项，不升级成政府举办批件。[L02][E01]
- **更名、译名、届次**：合法批准的单位更名/会议名称更正与原编号衔接时可通过；同名同城不同年不得直接复用批准。
- **机构授权委托**：经办教师和具体会议负责人可以同人；被授权学生可帮助传附件，但未经组织授权不能以学校名义给外方签发承办承诺。
- **双边会议**：旧L01明确“不适用本规定”，但2025总体会议规与其它可适用制度未澄清；不自动输出“无需审批”，走`POLICY_UNKNOWN`或正确业务归口。[L01][L02]
- **纯线上/零经费**：无需实体签证、酒店、交通和会后酒店结算，不等于不需要办会申请、预算来源说明、活动内容。[L08][E02]
- **跨学科会议**：科技、社科、宣传会签能叠加；实际主管归口不得由词典自动判断政治或学术倾向。[L02]
- **先获承办权再办会**：国际组织的正式授予权是有效机构证据，但没有校内/上级举办批件时仅标承办权已经获得。[L10][L13]
- **增列嘉宾**：会议本体合法获批时可保持原许可；新嘉宾申请因材料缺失而待批，禁止该嘉宾动作实施。若许可机关明文要求更改整体会议，则整案转重大变更。[L01][E03]
- **不可自动裁量**：学术价值、国际政策特殊条件、重大涉外风险、人员背景敏感审核、上级法定许可、专业保密与涉外纪律等由有权部门做人工作业。系统只能提示需有权核验的事实，不得代政府审查或生成真实批文。[L01][L02][L05]
