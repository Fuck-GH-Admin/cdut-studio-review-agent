### 1.1 独立审核目的与转介准则

**本模板收件先问：请求人是否在一个能够定位正式规则的“会议专项资助项目”中，申请本人对应具体届次会议的资格、若干可资助费用或其后续成果履约？** 否则：普通参会/请假转学生或教师出差请假流程；以导师科研项目日常出差或学科建设经费报销而没有独立专项资金审批的，转G07/T04；校际交换或长期访学选拔转G05-T03；因公出境许可转G05-T04；主办国际会议转G05-T06；研究生评优论文报告加分转奖励评优业务。转介不等于自动拒绝其它办理资格。

**三种真正的决定必须分开**：①本模板提供材料核验、客观资格事实与费用范围建议；②专项管理部门基于这些事实及名额预算进行真实资助决定；③实际参会后有权单位确认履约，财务部门独立验票和执行支付。状态之间不能靠一张学生上传“已通过”截图直接跳转。

## 2. 角色、对象、关系及权责

| 角色/实体ID | 定义与最小权限 | 不得推定 |
|---|---|---|
| `ROLE-01` 请求人/申报人 | 发起申报并明确实际要求的资助项目、款项或履约操作；可能与受益人相同 | 请求人可代学校作资助批准 |
| `ROLE-02` 受益人 | 有唯一学号/工号/博士后标识，属于该项目允许的个人 | 导师代签即导师本人受资助 |
| `ROLE-03` 有效代办人 | 经学校权限系统覆盖本项目、对象、操作、有效期的工作人员/导师/秘书 | 上传私人授权聊天记录自然取得学校签批权 |
| `ROLE-04` 导师或学院推荐人 | 项目要求时提供推荐/经费承担意见、院系身份核验 | 导师推荐等于主管审批通过 |
| `ROLE-05` 基金/专项主管部门 | 依据项目当年规则、预算与专家意见真正决定资格、额度、调整或撤销 | AI可代签资助批件或决定剩余额度 |
| `ROLE-06` 学籍/人事/项目台账管理部门 | 经授权提供在读、在职、历史资助、项目版本及批件状态 | 用户截图与已验证官方记录地位相同 |
| `ROLE-07` 外事审批部门（相邻G05-T04） | 对境外实际出访作出独立任务审批 | 会议资助批准产生出境批准 |
| `ROLE-08` 财务审核与支付部门（相邻G07/T04） | 核实费用、税票、汇率、实际支付与资金控制 | T01预估支持的金额等于可直接付款 |
| `ROLE-09` 学术会议主办方 | 出具通知/邀请/报告安排/会议变更/参会证明等 | 主办方自行承诺等于我校基金批准 |
| `ROLE-10` 审核Agent | 在明确政策和授权材料上给出分项、证据和规则可追溯的审核意见 | 独自改变政策、作实质科研择优、签章、发函或财务付款 |

**多对象语义**：同一届会议可能同时出现多位申请人；同一稿件可支持多位作者的论文事实但不带来共享资助额度；一人申报多类费用须各有`expense_line_id`。资助获批后如内容或会议发生更改，保留`supersedes`版本关系而不覆写原审批状态。

先确定 **具名专项项目**，后判身份、会议、报告方式、时限、额度及阶段。分支是项目条件，不是单独模板。

|---|---|---|

**组合规则**：`BR-01`必选；`BR-02`的身份主通道互斥（本科/硕/博/在站博士后/青年导师），但可叠加在外留学等状态；`BR-03`的国际属性、地点和线上状态是独立轴；`BR-04`的受邀报告、作者与实际报告要逐事实核，会议报告人可以与论文第一作者不同；`BR-05`会前/会后受理为项目配置互斥路径，合法后补邀请函是局部叠加例外；`BR-06～11`按条件叠加。任何两个同范围生效政策互斥又不能确认优先级时触发`POLICY_CONFLICT`，**不是按照字面最严或最新搜索结果取一个**。

定义`TRUE`=适用条件的必要事实已由有资格来源确认；`FALSE`=同样已有足以排除的证据；`UNKNOWN`=未提供、来源不可达、有效政策无从定位、值冲突尚未解决。条件为FALSE→`NOT_APPLICABLE`并写原因；UNKNOWN→阻断该规则的肯定或否定结果，继续执行不依赖它的其它审核目标。身份或财政历史无法查询不能拿申请人声明填为FALSE。

## 4. 全生命周期、阶段与门控

| 阶段ID | 阶段名称 | 允许判定/需要何时形成证据 | 有权下一节点 |
|---|---|---|---|
| `ST-01` | 资助项目与制度定位 | 项目/版本/学校匹配、不能从未知跳入拒件 | 视具体项目配置分流，不预设一条强制线性顺序 |
| `ST-02` | 接收申请与当前批次形式检查 | 依据项目阶段允许会前/会后申报、条件补件 | 视具体项目配置分流，不预设一条强制线性顺序 |
| `ST-03` | 资格与会议学术事实核查 | 学生/教师/博士后及稿件报告分支 | 视具体项目配置分流，不预设一条强制线性顺序 |
| `ST-04` | 预算逐行审核建议与专家评议 | 费用白名单、历史资助与预算；等待主管选择金额 | 视具体项目配置分流，不预设一条强制线性顺序 |
| `ST-05` | 有权主管部门资助决定 | 真实批准/部分批准/否决不可由作者代替 | 视具体项目配置分流，不预设一条强制线性顺序 |
| `ST-06` | 履行境外独立外事手续 | 仅实际境外出访触发；仅供引用G05-T04批准状态 | 视具体项目配置分流，不预设一条强制线性顺序 |
| `ST-07` | 参会及成果履约 | 资助任务完成事实，可能早于批复对允许后申请的项目 | 视具体项目配置分流，不预设一条强制线性顺序 |
| `ST-08` | 财务转接与归档 | 移交审批范围与证据，财务验票付款独立 | 视具体项目配置分流，不预设一条强制线性顺序 |

**节点依赖**：普通会前基金从`ST-01→ST-02→ST-03→ST-04→ST-05`，境外实体任务在成行前须由G05-T04另作正式许可(`ST-06`)，参会后进入`ST-07`，费用办理转`ST-08`。已允许会后申请项目，则会议事实/履约可能先于`ST-02`和`ST-05`，以事件时间+项目政策判定，不能通过序号大小否决。当前`ST-02`没有校方资助签章、`ST-05`没有会后发票均属合理，除非具体项目另有已到期条件。项目正式不批准后允许按制度补证、复议或再次评议，但模型不能覆盖有权否决。

## 5. 审核输入契约：四条隔离通道

1. **申报事项**：受益人ID、项目和批次ID、指定会议届次、需要执行的动作（申请资助/调整某费用/请求履约确认）、独立`expense_line[]`（用途/币种/请求金额/支付方/证据），`report_action[]`（报告人、类别、学术履约）。这些是待审请求，并不提供资助批准事实。
2. **申报材料**：申请表和预算、作者说明/会议相关性解释、导师意见（如项目明定由申请者提交）、变更说明、会后履约报告。学生或教师填写的“已获批准”只作为声明。
3. **证明材料**：主办方正式会议通知、邀请函、论文/摘要录用、稿件作者/署名单位、正式报告日程、参会证/屏幕记录、会议改期通告、费用承担函等。文字PDF可直接读取，纸质签名章扫描应保留图片视觉事实；OCR抽到“批准”须核签发主体。
4. **可信底账/有权数据**：学校政策版本库、学籍人事/博士后在站记录、会议等级目录、资助历史、金额上限、官方决定、撤回/退款、外事许可与财务流程记录。授权接口不可达→`DATA_UNAVAILABLE`，**不能将这类底账统一强制申请人自制截图上传**。

**固定来源引用最小粒度**：`case_id, application_id, subject_id/expense_line_id, document_version_id, parse_revision, original_hash, location(pdf页和方框/表格单元/段落/文件级), evidence_role, source_trust_level, linked_fact_id`。文件级无法定位就明示`location=file-only`，不得伪造页码或坐标。每次补件保留旧文书和新文书`supersedes`链、来源、时刻、审核版本。

## 10. 统一结果合同：分项状态、整案聚合与正式决定

**分项 `check_status` 状态**（一条规则针对一笔费用/受益人/会议/动作生成一项，不能省略未执行检查）：

| 结果码/状态 | 使用条件 | 后续职责 |
|---|---|---|
| `CHECKED_COMPLIANT` | 已按当前**有权生效**制度和可靠证据确认该条满足 | 可进入后续审批，但不是资金已批 |
| `NOT_APPLICABLE` | 该项目/身份/时间/当前阶段明确不触发该条 | 记录明确FALSE依据，不算缺件 |
| `MISSING_REQUIRED` | 生效规则明定本阶段必须，合法替代组也不存在 | 给补件清单、期限和责任人 |
| `CONDITIONAL_SUPPLEMENT` | 项目明许临时替代先受理、正式证据后补 | 保存允许依据、到期事件、未满足前不宣称最终完成 |
| `FUTURE_STAGE` | 会前事项却要求会后照片、发票或归国总结 | 本阶段N/A；待会后条件到达再触发 |
| `EVIDENCE_INCOMPLETE` | 已有部分必要事实或证据，但尚不能证明当前条款 | 有针对性补件，不下事实伪造结论 |
| `SOURCE_UNVERIFIED` | 文件已有但来源/签发主体不可核验 | 请求主办方核实或人工核验 |
| `CONFLICT` | 两份有效、相关来源在关键事实上有未解冲突 | 暂停涉及项、保留双证据并复核 |
| `POLICY_UNKNOWN` | 未确定当前有效项目办法/规则参数 | 先取得政策配置，不可套用外校限制 |
| `POLICY_CONFLICT` | 同适用范围有互斥有效政策且未获授权解释 | 由政策所有者决定，不自行取“最严” |
| `DATA_UNAVAILABLE` | 有制度但身份、历史金额、真实审批台账接口故障/无权查询 | 转授权数据接口或人工，不默认值0或FALSE |
| `INELIGIBLE` | 有生效且明确的客观门槛，权威事实已确认违反 | 告知仅该资助项目不合格，不连带禁止参会 |
| `EXPENSE_OUT_OF_SCOPE` | 该笔费用类别不在项目白名单 | 该费用行不支持；其它费用独立审 |
| `AMOUNT_OUT_OF_SCOPE` | 请求金额超过该项上限且上限已确认 | 分拆支持范围与超额，不能用预算当批额 |
| `AMOUNT_UNVERIFIED` | 费用/承担方/币种或累计额未能完成核对 | 对受影响行待核，合法已确认行不受牵连 |
| `PARTIAL_SUPPORT` | 一案多个费用行中至少一项有资格继续，另一行无支持或待核 | 保留每行意见；不是学校已经部分拨款 |
| `AUTHORITY_PENDING` | 导师/学院已完成有限操作，但后续有权基金或外事节点未批准 | 保留现有已审结果及下一责任人 |
| `MANUAL_REQUIRED` | 名额、学术水平、例外择优、安全/涉密/官方证据争议 | 生成真实人工待办，不自动决定批额 |
| `FORMALLY_DENIED` | 已有权部门有效否决决定 | 记录真实否决及救济/新版本；不被截图覆盖 |
| `FULFILLMENT_PENDING` | 获资助后履约证明未齐/仍可补 | 有权项目主管核验履约，不自动追回资助 |
| `FINANCE_HANDOFF` | 资助/履约信息已向独立财务域送交 | 需财务系统真实核销/付款状态 |
| `WITHDRAWN` | 正式撤销/撤回/取消记录已经生效 | 保留历史与重审触发；自述撤回不能替代正式状态 |
| `NOT_EXECUTED` / `EXECUTION_FAILED` | 作者计划中的核验尚未执行/执行异常 | 不能归类为检查通过或合理不适用 |

**有权业务决定另存**：`school_funding_decision`取 `PENDING / APPROVED / PARTIALLY_APPROVED / REJECTED / REVOKED`，每项都带`actor_id, role, decision_id, decided_at, source_system, approved_expense_lines[]`。只有主管系统/有权人签发的真实记录才能转状态；AI仅可输出`CHECKED_COMPLIANT`等材料核验意见。`approval`、`outbound_permission`、`finance_paid`各自独立，互不推断。

**整案聚合算法**：

1. 以`application_id`为主键列出每个`expense_line_id`、`report_action_id`、`beneficiary_id`的所有**本阶段适用**的规则结果；每个问题带`rule_id, code, severity, status, evidence_refs[], next_actor, remedial_action, affected_objects[]`。
2. `FUTURE_STAGE/NOT_APPLICABLE`不算失败；但`NOT_EXECUTED/EXECUTION_FAILED`计**覆盖缺口**，不能以其它规则通过遮盖。
3. 如果`POLICY_UNKNOWN/POLICY_CONFLICT`命中影响整个资助的根项目，则`case_gate=HOLD_POLICY`，但可以继续返回能独立检查的来源事实；如果`DATA_UNAVAILABLE/CONFLICT/INELIGIBLE/AUTHORITY_PENDING/MANUAL_REQUIRED`存在，则对应对象/动作处于等待、明确不合格或人工，不等于全案统一失败。
4. 合法项目明确不合格的主资格门槛可使本项目资助请求`ineligible`；已经发生的正常参会、之前真实学校审批记录仍不得覆盖或删除。
5. 对多费用行，逐行核支持类型、金额上限、有效财政历史；例如`registration=potentially_eligible`、`airfare=out_of_scope`、`accommodation=pending_data`，总体`case_gate=PARTIAL_POSSIBLE_NEEDS_DECISION`。若**所有行**都明确不支持且不存在履约办理需求，再汇总`NO_SUPPORTED_EXPENSE_LINES`；不能把某行不支持直接上升为“禁止参加会议”。
6. 任何没有有权决定记录的情况`funding_decision=PENDING`，即使所有客观资格规则均`CHECKED_COMPLIANT`。确认履约也不自动改变费用核销结果。

## 11. 补件、重审、撤回、变更与审计事件

- **受理/补件**：锁定原始`policy_profile`和`application_revision`；问题列表中每个缺件都带`rule_id`、当前阶段、合法替代证据组、补正期限（仅项目明示时）。申请人补交后新增`DocumentVersion`，不覆盖旧文档；若会议官方更正，标`supersedes`且复核是否改变资助范围。
- **变更/重审**：学籍、论文署名、报告方式、会议地点或实际费用类别变化，重跑该事实依赖的规则与金额行；资助主管人事权限或项目额度改变，影响资格/资金时由有权单位决定是否需重审。政策生效变更仅对规定适用时间和案件起作用，不无理由追溯重判已生效决议。
- **撤销/官方否决**：对本人撤回、取消资助、正式拒绝、复议变更分别留事件`actor+scope+time+before/after+source`，仅正式主管记录可改变`funding_decision`；禁止“最后一条上传文本覆盖全部结果”。
- **履约**：资助先批后履约，或国家专项先参加后获选，均由项目的时间政策决定。项目实际要求会后总结、汇报或证书时才进入该节点；某材料可以合法晚于会议日生成。
- **财务移交与归档**：输出主管已批支持范围及有据材料链；财务部门独立核票据、成本、预算和支付。资金若已退回，保留与原审批/付款链的关系；归档不代表所有历史材料均有效。
- **最小审计日志**：`event_id, actor_role, actor_id, at, target_scope, policy_snapshot_hash, template_version_hash, input_hashes[], rule_ids[], previous_result_id, next_result_id, approved_decision_source, manual_override_reason`。作者阶段仅规定这些字段，不创建真实业务日志。
