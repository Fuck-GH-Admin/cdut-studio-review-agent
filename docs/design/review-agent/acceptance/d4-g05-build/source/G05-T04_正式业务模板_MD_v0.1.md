## 1. 模板元信息、独立审核目的、适用及排除范围

**唯一审核目的**：在选定并确认适用的高校制度 profile 下，评价师生某一次因公出国（境）任务所需的材料和审批链是否满足**当前阶段**的业务责任，并对学校/外事有权系统已经存在的真实任务批件、人员范围、行程范围以及行前证照分别提供证据化状态。若处于线上涉外学术活动路径，仅支持学校政策明确要求的**线上报备**，不能转写实体出境批件。

- **覆盖**：教师单人短/长期任务；本科生/硕/博；博士后及合同科研人员在制度明确时；校内混合团组、外单位组团、跨国多城市、港澳、赴台、行程变更、撤回、归国记录、线上境外学术交流备案。每项以`application_id`关联某次业务动作。
- **不覆盖**：G05-T01会议专项资助择优或经费额度、G05-T03校际交流项目推荐和外方录取、G05-T05境外人员来校接待、G05-T06在校主办国际会议、G07/T04财务核销与付款、个人旅游签证指导、课程学分认定。有关这些事项的已批准记录只能作为本模板的**输入事实**，不能自动变为外事任务批准。
- **不得输出**：捏造的官方批件号、证照已领取、实际出入境事实、代签或代学校审查涉密/干部实质意见、报销已打款；所有这些动作必须来自有权主体的可信事件。

### 2.1 术语表（C1稳定业务语义）

| 术语 | 严格定义 | 排除的误解 |
|---|---|---|
| 请求人/发起人 | 发起本轮申报动作并对申报事实负责的人或有权单位 | 不等于所有实际出访者、不等于有权审批机关 |
| 出访者 | 任务批准所覆盖、真实需要行前证件的人 | 团长姓名出现不自动覆盖全部团员 |
| 证明出具方 | 对某项邀请、行程、学籍或签证事实出具原始证明的机构 | 不能直接替学校审批该出访任务 |
| 有权审批方 | 在既定权限及制度版本内可以作出任务或上级审批决定的机构/角色 | 模型、普通申请表或公示网页不是审批方 |
| 执行方 | 依法办理证件、行前准备或执行及归国管理的人/机构 | 审批通过本身不代表证件领取、旅行完成 |
| 材料槽 | 对特定事实和办理阶段的证据入口，可被多个合法证据文件满足 | 不等于每份材料对所有分支都必须上传 |
| 审核事实 | 经证据支持、可指出对象/时间/来源的命题 | 不代表学校已经给出同意或决定 |
| 任务批件 | 由有权机关签发、具有人员/任务/日期/地区范围的官方决定 | 不等于事前公示、外方邀请或项目选派成功 |
| 办理阶段 | 当前申请所处、会产生不同材料与权利事件的节点 | 不应将未来证件、归国记录倒推为初报义务 |
| 政策profile | 具体学校、政策版本、身份、目的地、项目和时期的适用规则集合 | 不能把多个学校各自严格条款拼成虚构的真实学校制度 |
| 等价证据组 | 证明**同一事实**且受该学校认可的OR可选路径 | 不能让不同权属层级的文书相互替代 |
| 权威状态 | 由可校验的主管系统实际产生的审批、证照或取消记录 | 不可由模型输出或截图字样自行创造 |

**键与作用域**：`application_id`（一次申报动作）→ `task_id`（一次出访任务）→ `group_id?`（一个团组）→ `membership_id`（团组内身份）→ `traveler_id`（每个实际人员）→ `visit_stop_id/segment_id`（访问与航空中转）→ `fund_allocation_id`（成员×项目资金）→ `approval_event_id/approval_document_id`（有权行为与批文）→ `document_version_id`（证据版）。同一审批结果只在明确的任务、人员、目的地、日期、动作、版本范围内有效。

## 3. 内部条件维度、优先级和未知逻辑

| BR ID | 条件轴 | 值与互斥/叠加 | 不确定值动作 | 依据 |
|---|---|---|---|---|
| `BR-01` | 任务模式 | `physical`或`online`互斥，`hybrid`拆成在线与实际出境两项操作；同案可并存两个作用域 | 请求可信会议安排/人工分流，禁止推为实体出境 | E02 |
| `BR-02` | 逐人身份 | `UG / MASTER / PHD / STAFF / POSTDOC / CONTRACT / SPECIAL`，逐人互斥主类型，特殊干部条件可叠加 | 查学籍/人事，不默认教师 | C01/E01/E03 |
| `BR-03` | 目的地 | `ABROAD / HK / MO / TW`作用于每个实质访问地点，跨国家可多选；机场转机事实单列`TRANSIT_ONLY` | `region_unknown`拒止地区特定义务并待核 | C10/C11/E01 |
| `BR-04` | 申报操作 | `NEW / SUPPLEMENT / CHANGE / WITHDRAW / CANCEL / POSTTRIP / ONLINE_NOTICE`，一次 `application_id`必须明确单一目标动作；需并行建动作对象 | 请求说明，不能默默猜成NEW | E01/E02 |
| `BR-05` | 当前阶段 | ST-01～ST-07，单个目标操作固定当前阶段，团员可到达不同子阶段 | 缺权威阶段→PENDING_AUTHORITY | C02/E01 |
| `BR-06` | 资助 | `PUBLIC / PROJECT / FOREIGN / SELF / MIXED`，逐人资金可混合、同一人多项目 | 财务待核，不因为校财务接口不能用而驳人 | C11/C08 |
| `BR-07` | 申请权限 | `SELF / LEADER / DELEGATE`，可按不同出访人/动作授权；授权有效期需覆盖操作时点 | 缺权限数据→AUTHORITY_MISSING而非授权默认成立 | C14/E01 |
| `BR-08` | 出访期限 | 由`policy_version`定义起算/端点/短长期，允许跨时区时间事实 | 无确认口径→POLICY_UNRESOLVED | E01/C02 |
| `BR-09` | 来源可信度 | 校OA/正式批文>A，原始邀请邮件/权威原件>B，申请人截图>C，个人聊天>D；不以外观美观度排名 | 同权威冲突→DATA_CONFLICT | B v0.2证据矩阵 |
| `BR-10` | 涉密/特殊权限 | 人事干部/涉密/特殊地区依授权部门决定，最小化只取审批元数据 | 脱敏后待部门结果，禁止接收明文敏感档案 | C02/E01 |

**三值评估**：每个条件返回`TRUE/FALSE/UNKNOWN`，另可`NOT_APPLICABLE`。`AND`只在所有必需已知真时真，任一假则假，否则UNKNOWN；`OR`只要任一有效替代证据组真即真，全部假才假，否则UNKNOWN；`NOT(UNKNOWN)=UNKNOWN`。对 `UNKNOWN`，**不激活与其不相容的宽松分支，也不宣称申请人违反严格分支**；只输出与此条件有关的 `POLICY_UNRESOLVED/DATA_UNAVAILABLE/PENDING_AUTHORITY` 并保存可确定的其他分项。对于显然独立、不以该条件为前提的字段核对，仍然继续。

**条件优先级**：先选制度与权限→申报动作及阶段→实体/在线→逐人身份与目的地（含TW独立上级链）→资金/期限/来访单位→必需证据及合法替代→批准/证照/变更/归国事件。`WITHDRAW/CANCEL`已经正式生效时阻断新的行前就绪；既有`FORMAL_REJECTED`不能被新提交材料覆写，只有有权复审/新案才可改变。额外的必要人审与签批不会因为所有文件齐全而消失。

## 4. 阶段合同（统一主干，不要求所有profile具有每一环）

| ST ID | 业务节点 | 最小审查动作 | 不能前置的文件 | 哪种状态可以由模型/学校分别产生 |
|---|---|---|---|---|
| `ST-01` | 新申请与材料受理 | 资格、身份、任务、受访方、路线、必需材料、申报操作 | 批件、签证、机票、归国报告 | 模型能建议`FORMAL_COMPLETE`；不能`TASK_APPROVED` |
| `ST-02` | 院系/职能审签及事前公示 | 教务人事财务适用条件、逐成员部门意见、公示完成与异议处理 | 真实机票/返国记录 | 部门已审只能由可信审批事件确认 |
| `ST-03` | 校内及必要上级正式任务批准 | 校方/上级有权批准记录、人员名单与批准范围 | 后续签证或返国总结 | 真实批件可标`TASK_APPROVED`；未批件保留`PENDING_AUTHORITY` |
| `ST-04` | 逐人证照及行前核验 | 任务有效、对应证件/签注/特殊条件/人事结果 | 归国公示和发票 | `MEMBER_READY`必须证照和许可均齐全；不代表模型发证 |
| `ST-05` | 变更、撤回、取消 | 原任务、旧/新范围、变更申请、有效批准或撤销事件 | 未成行不能索取实际出入境 | 原范围受保留范围约束；新增人员/地点不得自动继承 |
| `ST-06` | 归国执行核验及事后公示 | 实际人员、出入境/路线、夜航/中转、有权差异处理与总结 | 无实际成行不得索取此类凭证 | `POSTTRIP_RECORD_CHECKED`≠报销已完成 |
| `ST-07` | 线上境外活动备案 | 先核本校是否要求报备及备案结果 | 实体护照、航班、签证、出入境记录 | 只能`ONLINE_NOTICE_RECORDED`，绝不能出具实体批件 |

**阶段跳转**：任一阶段可因证据补件停留；审批否决事件进入`FORMAL_REJECTED`并保留申诉/重申路径；申请撤回/被撤销后不得继续沿旧任务执行；已批任务发生实质改变必须进ST-05并重审影响范围；自动化流程可建议`READY_FOR_HUMAN`，只有校方真正写入官方批准事件才跳入ST-03通过。

## 5. 输入契约：四种语义来源

- **申报事项**：一案内若干对象级的动作，例如`申请任务@task-1`、`变更路线@visit-3`、`证件核对@traveler-2`、`取消@task-1`。包含谁申请、何时、要做什么、目标范围及拟制理由。每个`item_id`有自己的对应证据与结果；并非PDF文本本身。
- **申报材料**：申请人制作/签署的OA表单或纸表、出访计划、任务说明、预算、团组人员清单、课程交接、变更申请、归国报告。申报材料可含事实主张但**不能自动证明校方已经批件**。
- **证明材料**：外方邀请/任务通知、会议议程、接收函、证照和签证等证明（含原始邮件、扫描图片PDF和官方电子证明）。纸质邀请函应保留版本、页码与真实性核验状态，不以图像中盖章像素直接断言真伪。
- **可信底账/授权接口**：校方学籍/人事、财政预算、OA审批日志/批文、上级台办状态、校方公示结束和异议处理、证件主管机关，**按权限获取**；接口失败是`DATA_UNAVAILABLE`而非申请人`MISSING_REQUIRED`。

## 8. 审核事实、跨文件关系和时间版本约束

**原子事实**（用于规则判定）：`FACT-PERSON-MATCH`、`FACT-TASK-BASIS`、`FACT-INVITATION-VALIDITY`、`FACT-DESTINATION-SCOPE`、`FACT-TRANSIT-ONLY`、`FACT-BUDGET-BY-MEMBER`、`FACT-POLICY-EFFECTIVE`、`FACT-DELEGATE-AUTHORIZED`、`FACT-PUBLICITY-CLOSED`、`FACT-TASK-APPROVED`、`FACT-HIGHER-APPROVED`、`FACT-MEMBER-DOCUMENT-READY`、`FACT-CHANGE-APPROVED`、`FACT-ACTUAL-TRAVEL-CHECKED`、`FACT-SENSITIVE-AUTH-CHECKED`、`FACT-ONLINE-NOTICE-VALID`。每项包括`subject_key`、`as_of`、`tri_state`、`evidence_refs`、`trusted_issuer`、`policy_profile`及`rule_id`。

- **跨文件**：一个国家多城市可能多个接待单位；对每个`visit_stop_id`检查邀请和任务依据，不要求纯`TRANSIT_ONLY`节点提供访问接待函。`flight_segment`的国家不等于一定`immigration_entry=true`，仅航段信息不足证明未入境。
- **逐人财务**：`group_total = Σ(traveler × project × amount)`必须有币种/汇率口径；金额矛盾先问财务，不通过简单相加直接批准预算。一个团员金额待核不能清空别人的已核事实。
- **生效日期**：邀请函活动期不等于必须严格等于离境/回国当天；是否允许必要交通日前后日由`P-*`规定。跨时区航班和过境记录不能只按日期字符串比较；没有校规宽限不允许自动设“一日容差”。
- **版本性**：`task_approval`与`public_notice`使用两个对象；`approval_issued_at`,`approved_member_ids`,`approved_visit_ids`,`approved_period`,`revoked_at`与`change_approval`版本序列形成唯一有效范围。文件本身上传于新日期并不证明批件后来修订。
- **授权权限**：`delegation_scope`与生效时段精确指向某业务动作和被委托人。C14仅证实通用砚湖易办功能，不证实G05-T04允许该种委托。
- **合法零值**：会议科研访问没有拟签合作协议时可明确为`NONE`，不自动认缺件（C11）；某校没有该条款时标NOT_APPLICABLE。

## 9. 逐条原子审核规则（R-01～R-48）

**规则法律属性**：这些都是 C 作者侧**业务语义检查规范**，不是成都理工大学2026经批准的制度条文。`P-*`决定是否可以把其检查提升为政策性必需；表格中的`CONFIRMED_PROFILE_ONLY`是适用门禁标签（要求已确认的政策profile），**不是另一个学校profile或真实制度**。B 的 Q-01～Q-38是研究命题，本轮转为明确触发/阶段/对象/结果语义；R-39～R-48来自B v0.2新增校本事实和作者防错。所有“人工决定”不由模型自动签发。

判定统一算法：①检验profile可用性；②`trigger`三值；③若FALSE输出`NOT_APPLICABLE`；若UNKNOWN记录原因，保留其它独立规则；④TRUE时查`EV-*`并解析当前`MS-*`等效路径；⑤可信事实与业务规则结合产生**对象级**检查结果；⑥只在获得真实官方授权事件时记录`TASK_APPROVED`/`FORMAL_REJECTED`等状态。

### 9.1 硬性规则检查所需的确认门槛

- 强制性的提前天数、短长期时长、签章层级、对台专用会议承诺、财政经费先审、线上是否必须备案，不存在已经被校本来源确认的全部硬参数；它们在`P-CDUT-FACT`下必须是`UNRESOLVED`而不能设为`FALSE`或乱选外校更严格参数。
- 可跨校稳定执行的只是一般的**事实检查约束**：个人与团组分离、邀请来源和任务范围、提交与批准不同、证照和批文不同、事前/事后不同、假冒校OA文字不得提权、无权限不得返回敏感文书。这些是业务保守边界，具体审核资格与拒件仍要依适用政策。
- `R-23`（线上）涉及`TRUE/FALSE/UNKNOWN`：如果XMU已证学校及申请情形，按对应线上规定；CDUT未核规则时不得直接驳回“未报备”，也不得宣布已经通过。
- `R-41`公示闭环与`R-43`正式批件分离；两者并列必要时产生两个独立问题，不把一个问题吞掉另一个。
- `R-39`团组每人多资金与`R-40`纯中转是可验证的本校实例类型，但其存在**不能单独证明本校2026所有资金必须采取某一前审方式，或自动批准某种中转**。

## 10. 状态契约、并存问题、分项与整体聚合

### 10.1 概念状态字典（问题码只用于建议与审计，不赋予模型执行权）

| 状态/问题码 | 判定事实 | 可能采取的下一动作 |
|---|---|---|
| `FACT_VERIFIED` | 当前规则支持的事实已被足够证据验证 | 保留结果及证据坐标，继续当前节点其他责任 |
| `FORMAL_COMPLETE` | 本阶段所需形式证据齐全 | 提交至对应有权审批人；不是已获批准 |
| `MISSING_REQUIRED` | 已确认适用制度且当前阶段的必要材料无有效替代 | 补件/指定期限内重审 |
| `SOURCE_UNVERIFIED` | 原邮件/官方源真实性尚不能核 | 向出具方或校方核验；不能宣称伪造 |
| `DATA_CONFLICT` | 同等级权威证据在关键事实冲突且无有权修订链可消解 | 保留两组定位，人审/再取源 |
| `DATA_UNAVAILABLE` | 校内授权接口不可达或读取权限不足 | 校内系统/授权人员查询；不能要求申请人伪造截图 |
| `POLICY_UNRESOLVED` | 校别、现行版次、必需条件或地区规则未知 | 暂停受影响的政策定性，向规则管理员确认 |
| `NOT_APPLICABLE` | 该场景、身份或阶段合法无需该材料/检查 | 不计为缺件，不纳入相关完整度分母 |
| `AUTHORITY_MISSING` | 委托、院系、财务或外事应有权节点尚无可核授权事件 | 转有权审批；拒绝越权执行 |
| `PUBLICITY_NOT_CLOSED` | 本阶段需要公示，但期满异议处理未闭环 | 保留公示状态，提交有权管理人确认 |
| `PENDING_AUTHORITY` | 形式审查可结束，但必须由学校/上级独立审批 | 只显示待审批，不能生成已批 |
| `MANUAL_REQUIRED` | 专业安全、敏感人事、涉台等实质裁量事项 | 转具体有权限部门，最小暴露证据 |
| `FORMAL_REJECTED` | 真实有权机关明确正式不予批准且仍有效 | 不得用模板结果覆盖；按复审/重申流程 |
| `TASK_APPROVED` | 存在真实有效官方任务批件、范围覆盖目标 | 逐人进一步检查证照和行前手续 |
| `MEMBER_NOT_READY` | 该人的证照、签注或行前事项尚未满足 | 保留任务批准事实，仅限制此人执行 |
| `CHANGE_NOT_APPROVED` | 有新邀请/变更申请，但无有权更新批件 | 暂不得按新范围执行，继续核定旧范围是否有效 |
| `CANCELLATION_PENDING` | 已提出撤回/取消，但批文效力还未由有权机关确认 | 交主管确认，对未批准动作停止新的执行 |
| `REVIEW_STALE` | 政策、申请、证据或批准版本改变使既有检查过期 | 以版本差异只重审受影响对象与规则 |
| `PARTIAL_PROGRESS` | 同团/同案不同人、国家、财务节点结果不同 | 展示每对象状态及阻断项，不汇总为“全员通过” |
| `POSTTRIP_RECORD_CHECKED` | 归国报告与实际路线等已核对 | 依学校规则继续归档/公示；报销转其他模板 |
| `ONLINE_NOTICE_RECORDED` | 经适用制度与有权部门线上报备确认 | 仅线上备案，不构成实体出境批准 |
| `EXECUTION_RECORDED` | 实际执行/证件领取等由有权系统产生记录 | 仅陈述可核的已发生动作，绝不由模型凭文本创建 |

### 10.2 部分结果与汇总优先级

- **原子对象**：`(application_id, item_id, task_id?, group_id?, traveler_id?, visit_stop_id?, budget_allocation_id?, stage_id, rule_id)`；每次回执可有多个`issue`及多个独立事实，不设“全案一个布尔通过”。
- **不可覆盖事实**：若有真实未被撤销的`FORMAL_REJECTED`，针对对应任务或成员不得写成已通过；若批件尚未形成，任何自动形审结果都不得生成`TASK_APPROVED`。
- **聚合阻断顺序**：有效正式拒批/撤销 > 任务批准范围重大冲突/缺有权权限 > 现行政策未知与上级未批 > 校内接口不可达/同权威证据冲突 > 当前阶段必需材料缺失 > 当前阶段可核内容合格。顺序只用于显示**阻断理由**，不能覆盖并存问题或丢失已批局部结果。
- **部分推进**：团组任务有真实批文，4人中3人证照齐、一人尚未办证；任务为`TASK_APPROVED`，个人为3项“行前材料已核/待有权执行”、1项`MEMBER_NOT_READY`，汇总`PARTIAL_PROGRESS`而不是一整团已出行。
- **材料完整度≠有权同意**：`FORMAL_COMPLETE`是建议；`TASK_APPROVED`来自真实权威系统事件；`EXECUTION_RECORDED`来自实际业务执行记录。

## 11. 全生命周期：补件、重审、权限变化与执行记录

1. **首次提交**：固定学校规则版本、申报动作、当前文件快照；生成`application_id`和逐对象计划；材料不足允许在制度规定窗口补正，补正不自动签批。
2. **补件**：新文件产生新`document_version_id`和hash；重评其影响的事实、证据组、R规则及所在成员/停靠点，既有有效不受影响的权威事实保留，但禁止过期检查继续引用旧文件版本。
3. **权限/身份变化**：授权到期、学生毕业、成员退出、变更团长、人事特殊岗位改变，重评对应`BR-02/BR-07`及所有有依赖的规则；数据源不可读不得默认为有效。
4. **政策变化**：按规则生效时段/过渡条款选择适用版本，未知需制度管理员解释，不静默套用最新最严版本。
5. **正式批准**：只消费有权机构实际提交/核验的批件和范围，记录`approval_document_id/version`；不能使用申请人自行录入的“已批准”字符串转状态。
6. **出境前证照/行前**：按真实任务范围与逐人证件、签注/签证及必要培训审核；一个成员未就绪不自动取消其他成员资格。
7. **变更**：新旧范围以`change_request_id`连到原批件，待有权批准后才能更改有效访问范围；仅申请变更时不擅自生成新批文。
8. **撤回/取消**：审批前撤回→停止申请流转但保留历史；已批任务的取消须有权机关事件；涉及证件回收或资金退款需执行方另办。
9. **正式拒批/复审**：已生效否决不能因补件而被模型抹除；复审需要符合制度的有权新决定和关联版本。
10. **归国/公示**：出入境记录和实际路线、夜航异常、主管报备、总结及后公示按条件出现；事前不得要求，财务结算转G07/T04。
11. **输入/软件变更**：模型、规则版本、OCR解析修订、材料hash变化均使相关审查回执进入`REVIEW_STALE`或要求重新定位证据，不允许旧回执跨版本复用。

## 12. 合法例外、替代与人工审核边界

| 例外 | 合法处理 | 非法简化 |
|---|---|---|
| 仅过境不出机场 | 作为中转节点，实际是否入境依权威事实；访问国与中转国分离（C10/C11） | 途经香港/埃塞俄比亚就判新增访问国，或仅凭航班证明绝未入境 |
| 个人自费或外方全额资助 | 视学校资金profile检查预算说明及校内是否有实际前置义务 | 一律要求科研项目经费号或全免审批 |
| 一人多个经费项目 | 逐人×项目×币种计数与审批，合法为多来源（C11） | 只用团组总金额一项覆盖全人 |
| 团组混合学生与教师 | 同一任务不同个人身份/审批/办证路径 | 以领队一张证件推全团可出境 |
| 非会议学术访问或纯报告 | 外方接收函/科研访问计划可作任务证明；“拟签协议=无”可合法（C11） | 强制提供论文录用或协议签约 |
| 邀请函早于批准但许可尚未形成 | 邀请可证明任务存在；等待校方有权批件 | 凭邀请函直接“已审批” |
| 旧试行校规仅适用特定教职工访学 | 使用历史限定profile或待学校确认现行效力 | 视为成都理工大学2026所有出境统一强制要求 |
| 线上境外活动 | 学校规定时形成线上报备，不收实体出境资料 | 完成线上备案便出具出国任务批文 |
| 公示存在但异议不明 | 要求有权公示闭环确认，非一概认无异议 | 公示表“处理意见”空白就视已批准 |
| 夜航跨天 | 核实际时区、边检和主管部门认可与否；无法核则人审（C07） | 自动宽限一天，或自动认定造假 |
| 部门和接口不可访问 | `DATA_UNAVAILABLE`，转校内授权查询 | 逼申请人上传人事原件、硬判漏件 |
| 正式申请代理 | 只在授权业务代码、期限和操作权限覆盖时允许 | 通用平台委托即获得外事签批权 |
| 证件照片、干部档案涉敏 | 最小化、脱敏或取校方核验结论 | 把真实明文护照/干部资料喂通用OCR训练 |
| 同等级官方版本冲突 | 查询签批时点和修订链，仍有冲突转人审 | 以PDF最后修改时间或更清楚的扫描为准 |
