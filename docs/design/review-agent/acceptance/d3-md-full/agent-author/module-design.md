# 独立业务建模 / 模块选择

## 技术平面

**单一模板** `g01-archive-utilization@1`。D1工作区包括本地独立职责模块（不是自称已冻结共享模块）；三个档案件与五个操作目标：`i01/read`、`i01/copy`、`i02/read`、`i03/borrow`、`i03/excerpt`，另有三个item目标；`certified_copy`因D2操作枚举缺失显式阻断。

R08双方身份独立Check，R09代理对象、R10日期/方式独立Check；read、copy权限分别是R21/R23，绝不共享同一授权状态。R18开放与公布独立判断；R33审批待办与R32材料义务独立。条件适用性、证据提供者、操作与版本仍须由实际适用校规/可信服务确定。

## 为什么当前不复用B01/B02

已有冻结共享资产的D3-10技术片段只证明有限范围内的两个局部语义，不能承担完整档案业务资格、档案开放、隐私与部门授权。此次独立`PROFER_CONFIG_DIR`没有预先安装冻结共享资产；未经`discover/inspect`实际验证digest的模块不能手写锁冒充复用。为了不从其他Agent成果反推业务，先保留11个workspace-local模块；不修改冻结公共版本。后续如有可审计的freeze/reuse证据，再仅抽取确实等价的局部责任。

## 能力缺口与拒绝降级

D2的`scenario`强制绑定单个campus-card，因此不能用它表达多维组合条件；`RuleSpec.when = {all:[]}` 只有任务文字说明，**不是可执行条件树**。同样无法忠实表达申请人/审批部门不同提供者及`requiredAt`；电子凭证OR、历史更名替代、证据真实性与版本依赖、多个并存结果均需高级映射或人工权威决定。见gaps；对应保留原R号且不算运行支持。

修订v1→v2目前只是**作者态JSON预备文件**，尚未在真实D1 save/read/diff中落盘；`archive-r2-advanced-blocked.json`专用于验证高级关系不被静默忽略。
