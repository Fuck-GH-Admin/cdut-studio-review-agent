# 无损模块化的语义边界（实现中立）

## 可以共享“局部能力”，但不能共享行政许可

| 局部语义 | 可复用内容 | 必须保留的专属/独立输出 |
|---|---|---|
| 身份/历史关联 R03/R04/R07/R08/R40 | 可信身份比对、曾用名与机构沿革、双方身份证明 | 身份成立不是档案许可；代理双方与私人权利主体仍独立 |
| 委托/单位授权 R09/R10/R11/R12/R13 | 授权人-代理人关系、有效期、范围包含、签署来源 | 私人委托、单位职务授权、档案馆最终许可为三种权利关系 |
| 条件材料 R27/R29/R32/S01–S14 | 证据槽、可信等价替代、读取进度与到期阶段 | 电子委托可验并被接受≠获得馆方利用批准；纸质固定形式不普遍强制 |
| 规则适用 R01/R30/R31/R39 | 学校+时间窗+角色+操作+阶段版本解析 | 外校参考不可偷偷提升为受理学校现行政策 |
| 细粒度授权 R21–R26 | 每操作权利覆盖的参数化核验框架 | view/excerpt/copy/certified_copy/borrow_original 是不同决定，不是同一布尔结果 |
| 来源与差异 R17/R18/R28/R38/R42 | 证据版本、SourceRef、比对、文件覆盖状态 | 馆藏开放性/已公布/限制级别三者正交；OCR/提交人材料不具权威 |
| 工作流 R33–R37/R41 | 当前阶段、人工待办、每项状态与整案摘要 | 后置审批和交付由有权人；业务结果不可合并为单个合格位 |

**形式相似而不可合并**：一份证件证明身份、单位函证明因公经办、委托书证明私人代理、馆方许可证明实际利用权限、交接回执证明已发生物理执行——五类文件可能有相同姓名/日期/印章，但可证明命题、签发主体、阶段与法律效果不同。同样，`目录可见`、`已开放`、`可查阅`、`可复制`、`可外借` 必须分开。

## 独立 Check 与等价自由度

- 必须**可分别观察**：R08 身份双方、R09 委托对象、R10 委托操作/期限；R11 经办资格/R12 函件范围/R13 私人委托独立性；R17 馆藏、R18 公布与开放、R19–R20 限制及人工权利；R21–R25 五类操作；R27 真伪、R28 冲突、R29 替代；R32 到期缺件、R33 待有权审批；R35 逐操作、R36 部分聚合、R37 门控、R38 未读、R39 校规权威、R42 版本过期。
- **独立可观察 ≠ 一条原文必须独占一个节点**。共享模块内可有多个 Rule/Check，或同一检查框架实例化于不同 `subjectId`；只要局部事实、范围、未知/不适用、来源和结果保真即可。
- 允许 R01/R30/R31/R39 共享规则匹配算子，但**不得因此把时间有效、学校来源、渠道和适用性只变成一个通过**；有冲突须分别能解释。
- R24、R25、R34、R37 的正式授权/借还/交付不要求让 Pi 自动签批；可以是独立的、可信的**人工/业务系统门禁**。没有已实现的执行权时标 `manual-only` 或 `tooling-blocked`，不伪造成功 Check。
- 条件维度 Bxx、材料槽 Sxx 与反误杀 Exx 可以通过可靠结构、证据绑定、状态/范围条件或回归测试承担，不强制各自占用独立 Check，但必须有可追踪的验证去向。

## 必须参数化的五个轴

`case_id + item_id + operation_id` 是业务键；授权还要绑定 `requester/principal/authorizer`、`operation scope + pages + copies`、`validFrom/validUntil`、`review_stage` 和 `rule-version/evidence-version`。一份附件可引用多次，但每次引用具有自己的支持事实和范围。未知与已证伪不可合并。

## 可能超出当前 D2 的无损编译范围

1. 强结构的跨主体身份链与电子委托的等价证明、有效期及操作集合包含关系。
2. 有权审批与合法委托分别存在的多关系、同案单位+私人委托叠加。
3. 材料槽的双时钟：申请时到期、审批责任方签批、交付后归还。
4. 授权逐页/份数及混合档案件逐操作差异、阶段性的合法替代。
5. 数据源可信性与规则现行效力必须同时满足的 SourceBinding。
6. 冻结版本与旧 Run 不漂移、改新材料有针对性重审。
这些是**待验证能力边界**，不是没有实测就断言 D2 必然失败。如果 D2 `D2_UNMAPPED_ADVANCED` 安全拒止，应报告 TOOLING-BLOCKED，而不能称已无损执行。

## 禁止的“编译绿灯”推论

编辑器或 D2 `validate/preview` 成功仅证明有限结构有效。不能证明 Rxx 覆盖、未知状态恰当、源法规生效、Pi 自主读完材料、电子替代没有误杀、实际批准已存在。所有金标预计均在未来第三方用真实 Rule/Check/Subject/SourceRef/Run 核验，而不是现在预填 Check ID。
