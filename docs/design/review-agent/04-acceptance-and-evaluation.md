# 通用审核 Agent：最终验收与评测

日期：2026-10-03。本文为**待执行验收方案**，所有阈值是拟定交付门槛，并非已达到的性能或准确率。

## 1. 怎样才算做完

完整本地通用审核 Agent = **全部 A 类功能验收 + 全部 C 类接入契约验收 + 固定材料集评测 + 安装包/易用性验收**。六个模板都应有完整业务闭环，第七种业务能只靠模板配置运行。

真实校方联网版另需 S 类验收；学校还没有接口时，可以完成本地版及接入契约，但不能把 Mock 的身份/权限/回执说成真实校方能力。所有必需验收记录为通过/失败/未执行，未执行不等于通过。

以下情况均不能作为完成依据：能输出几个问题卡、engine=ai、截图漂亮、只跑内置 fixture、模型说“我检查了”、现有 56 个单元测试通过，或只有无异常的 happy path。

BDD 用“给定/当/则”描述。每条保留输入版本、实际输出、来源定位和操作记录。固定正确性样本用离线回复测试保证可复现，真实模型另按第 5 节评测。

## 3. 确定正确性样本与预期值

全部业务数据虚构，规则在样例政策中明确写出。每个样本保存原件、规则版本、预期检查与引用、预期动作/分数。下面为**拟制作的材料规格**，本次设计文档未新增实际测试材料。

| 样本 | 必需输入 | 预期值/行为 |
| --- | --- | --- |
| D01 全符合 | 明确资格/时间/证明/分值，每条来源齐全 | 检查全符合，findings=[]；AI 空清单合法，无 mock 降级 |
| D02 等级错报 | 申报一等奖，证书二等奖，已确认映射 6/3 分 | 等级不一致可回指两处，建议规则分 3；最终值由决定记录 |
| D03 多证/共享 | 2 张图支持同一事项，1 张合影支持不同学生参与 | 正确多对多；仅相同证书或图片重复不直接判重复计分 |
| D04 择高与上限 | 同 event E1 的 6/3 分择 6；E2=5；组上限 10，按高分优先分配 | 原可计 11，组计入 10，明细 E1=6/E2=4，被舍弃 E1 重复项=0；每次重放一致 |
| D05 权重与零值 | 智育 85、德育 90、加分 95、体育 80；权重 0.50/0.30/0.15/0.05 | 总分 87.75；0 值有效；其中一项缺失则等待，不当 0 |
| D06 金额/币种 | 123.45+76.55=200.00；允许限额 180.00；另附币种不明的一笔 | 已知组可报 180.00/超 20.00；未知币种另待确认，不偷偷纳入合计 |
| D07 日期边界 | 规则含开始/截止当日；前一日、起始日、截止日、后一日 | 首尾当日符合，外侧不符合；未知时区/日期解释待确认，保留原文 |
| D08 补件并复审 | 缺必需证书，先补模糊图再补清晰图 | 第一次已回复但未满足；第二次核验满足、增量重审；保留两次回复 |
| D09 政策冲突 | 两份已启用政策同组上限 10/12，无覆盖声明 | 受影响结果待确认；选定优先关系后按正确版本重新计算 |
| D10 伪引用/漏页 | 模型返回不存在的来源 ID；9/12 图仅处理 8；扫描页失败 | 假引用不成为已验证结论；漏页列出未检查；全通过条件不成立 |
| D11 评委 | 维度权重 0.4/0.6，1–5 分；J1=(4,5)，J2=(3,4)，J3 回避；需 2 个有效评委 | 分项均值 3.5/4.5，汇总 4.10/5；若映射百分制=82.00。J2 未交则未达人数，不以 J3 或缺评补 0 |
| D12 配置新业务 | 实验室组织申请，人数上限 20、用途与时段/计划附件要求、两级流程、无分数 | 生成对应表单/检查/报告，无学年/申报分强制字段，流程确实可处理到决定 |

同分/名额另设两项目总分相同样本，分别验证“共享排名”“按指定维度”“交组织者裁定”三种已配置策略。没有策略时不按姓名或随机顺序定名额。评分 N/A 设单独条件样本，验证模板的分母策略。

## 5. 模型评测：怎样证明没有“只会说”

### 5.1 评测集组成与真值

拟建立 120 案公开可分发的虚构/许可样本，每个内置模板 20 案；每类包含全符合、明确违规、缺件、歧义、无法识别、制度冲突和修订。至少 30 案含图像/扫描，20 案含多依据，20 案含跨文件；这些集合可以交叉。另留 30 案不用于 Prompt 调整的盲测。

标注记录：适用规则、事实与可接受来源、每检查项状态、确定数值、补件动作、整体建议允许范围。两位了解该业务的标注者独立审阅，差异裁定后锁版；没有明确业务规则的主观项允许待确认或合理范围，不能用单一人的偏好伪造唯一真值。

角色走查需要真实同学/老师/评审者参与，目前本轮只有角色推演。评委场景评 AI 的摘要忠实、量表遵循和建议是否有依据，不以“和某个评委分数完全相同”衡量真实性。

### 5.2 拟定质量门槛

| 指标 | 定义/分母 | 交付门槛 |
| --- | --- | --- |
| 登记和覆盖账本 | 实际导入文件/页/计划检查与记录对比 | 100% 有成功/部分/失败/未执行记录；不允许静默遗漏 |
| 确定计算/状态 | 固定 D 集与业务状态机 | 100% 与真值相符，重复执行一致 |
| 引用存在性 | 交付的“已核验”结果引用索引/范围 | 100% 存在并属于正确版本；非法引用一律非确定结果 |
| 来源支持性 | 核验结论是否被引用内容支持，独立人工评估 | ≥95%；影响通过/拒绝的明确结论在固定关键集 100% 有支持 |
| 明确违规召回 | 规则/事实清楚的违规检查，被正确识别数 / 标注违规数 | ≥95%，资格否决/上限/互斥等关键固定项 100% |
| 明确违规精确率 | 正确的确定违规 / 系统交付的确定违规 | ≥90%；全符合固定集不得误拒绝 |
| 歧义处理 | 不可读、规则冲突、证据不足真值中，正确待处理比例 | ≥95%；固定异常集不得自动通过 |
| 结构化提取 | 关键字段精确匹配（标准化后），并追踪来源 | 清晰电子材料 ≥95%；扫描/图像单独报告，不混合平均遮盖弱项 |
| 全符合案卷 | 适用检查完整且符合时整体建议 | 固定集 100% 合法零问题；不生成 fixture 问题 |

以上阈值只适用于固定版本、声明支持的材料类型和记录的模型配置，不能延伸为“任意学校任意材料准确率”。同一个模型对固定关键集至少运行 3 次，关键资格/计算/引用不变量每次都满足；数值与条件由程序执行，语义波动留下待确认。

报告记录模型/渠道类型、Prompt/模板/规则/解析版本、调用量、耗时、失败/重试、每类型准确率与错误样例。比较升级时沿用锁定盲测集；通过复述预期答案的模型 stub 只能测试软件行为，不能作为模型准确率。

## 6. 自动减负和易用性验收

用户知道基本使用方法。目标是减少实际整理/核对劳动，不考查是否读教程。

| 场景 | 拟定门槛 | 测量方法 |
| --- | --- | --- |
| 首次运行 | 安装→示例完整结果无需终端/开发配置；首次真实模型最多一个全局配置入口 | 新环境录屏，记录所有额外操作 |
| 已有模板单案 | 选模板、交材料、一次开始；全部可自动步骤连续完成 | 记录必需点击，不把文件选择/真实业务歧义计入无效操作 |
| 模板负责人 | 5 位未参与开发者中至少 4 位，30 分钟内完成 D12 的创建/试跑/发布 | 只允许普通界面；不能开发人员代写 JSON/Prompt；记录卡住位置 |
| 原件核对 | 从问题卡一次动作到正确材料/依据；窄屏可返回同卡 | 覆盖多文件/多出处/PDF/表格/图片，人工逐条检查 |
| 批次减负 | 同一标注批次相比逐文件手工核对，整理/重复输入动作减少 ≥70%，人工活跃时间减少 ≥50%，且质量达到第 5 节 | 用相同任务/人群比较，记录基线；模型等待单独报告，不能拿等待冒充工作时间节省 |
| 处理闭环 | 学生能看懂补什么、老师能确认剩余事项、评委能独立提交 | 每角色至少 2 人走完真实任务；零开发人员干预完成一轮 |
| 错误可恢复 | 失败有原因/未完成范围/下一步；恢复不重复已完成业务动作 | 断网、杀进程、取消、重复导入、版本冲突演练 |

可以另展示 AI 自动完成的准备项数量，但不能把“发起一次模型请求”统计成完成一次审核。

## 7. 性能、包体与资源验收

先使用一台可说明配置的 Windows 演示/目标机与 Linux 开发机测试，记录 CPU/内存/磁盘、安装包版本、OCR资源、模型与网络。以下作为工程目标：

- 输入后 1 秒内显示任务已登记及阶段，不在 UI 线程读大文件/OCR。
- 停止请求后 2 秒内 UI 显示停止中/已停止；若底层无法立即结束，禁止后续决定/回写，并如实显示。
- 100 案/500 文件队列可管理，单坏文件不影响无依赖案；按配置并发和模型限流，报告峰值资源。结束时文件账本和检查账本完全对得上。
- 关闭再打开能恢复案卷、待办、历史、评分与已提交检查点；不得从第一步重新发出补件或回写。
- 不设脱离模型的“一切 30 秒完成”承诺。分别记录解析、OCR、模型与总耗时的 P50/P95，UI 显示真实阶段；容量/预算限制形成可继续的未完成清单。
- 打包的 OCR/解析依赖在目标平台验证，清晰报告必须联网的推理和本地可完成的计算。示例可离线演示，真实语义审核要求已配置可用模型；这项前提由引导完成，不留给用户安装底层工具。

## 9. 交付证据清单

1. 六模板发布版本、可导入模板包、D01–D12 的原件与真值、120 案评测清单及锁定盲测。
2. 每条 A/C/S 的结果与输入版本；不能执行的 S 说明缺哪项外部配置。
3. 三条完整录屏：学生补件/申诉→老师定稿；整批综测→名册；独立评委→汇总→同分/名额→反馈。
4. 并发、重启、取消、错误能力和旧结果演练记录；引用/覆盖/分数的独立核对。
5. 可安装产物、新环境使用记录、解析/OCR依赖验证、模型配置与资源报告。
6. 对应模板/运行/规则/模型/解析版本的报告、交接包和 Mock 接入回执。

只有这些证据支持，才能宣称“用户只配置业务模板，系统显著减少整理与审核劳动，并能完整处理结果”。当前代码审查和调研支持设计方向，尚未证明这些目标已实现。

## 10. 补强回归用例与验证边界

### 10.1 H01–H16 的逐项回归

K 类是原业务完善计划合入后的定向回归，补充 A 类验收，不能替代完整交付。编号与 01 的 H 条目一一对应。以下仍为待执行用例，不是已通过记录。M0 允许显式未检查的暂存状态；最终验收仍要求目标必需格式、自动分批和业务闭环真正可用。

| 回归 / 关联验收 | 给定与操作 | 具体通过条件 |
| --- | --- | --- |
| K01 证明 / A03/A04/A08 | 一份含唯一识别文字的 TXT 证明、12 张带不同编号的图片；其中一张超过单请求资源限制；查看请求与结果账本 | 13 份源文件全部登记、原件 ID 可回溯，文本原文和出处进入检查；每张图有已处理/待处理/失败及原因，不因第 9 张以后消失。M0 的缺口必须可见且阻止完整符合；M2 分批/压缩或替代读取完成支持范围，每个事实/待确认都关联真实来源 |
| K02 多依据 / A06 | 两份启用依据各含唯一条款，只有第二份规定的要求被违反；再加入相反限额 | 请求/执行计划含两份来源，第二份能触发对应检查与真实引用；冲突仅阻断受影响检查，选定优先关系后按确认版本执行。停用依据不参与本轮，但保留历史 |
| K03 无演示污染 / A01/A16 | 自建案卷在无模型/超时/JSON错误时生成规则；再用带演示 ID 但无有效 fixture 来源的案卷，及真实修改后的演示副本 | 无未经确认的演示校规/锚点/分值混入；保留已确认规则和失败范围，提供补充/重试入口。显式模拟模式只能读匹配 fixture 并标来源；单有 ID 不能触发模拟回退 |

### 10.2 验证范围与发布门禁

1. **文档整理**：核对迁移条目、ID 对应、相对链接、代码落点、Markdown 结构和删除文件引用，不因纯文档改动重跑整套产品测试；记录“文档已核查”，不写“功能已修复”。
2. **功能提交**：运行受影响 K/BDD 复现及相应服务/状态测试；共享类型或 IPC 改动增加类型检查和 main→preload→Renderer 的实际调用验证。是否扩大到全量测试依据共享影响及仓库门禁，不机械要求每个局部批次都跑全部测试。发布阶段执行适用的全量 `bun test --isolate`、类型/构建/打包及本章端到端验收，失败有明确记录。
3. **界面证据**：用当前构建的原生 Electron 走导入、运行、切案、恢复、联动与导出。CDP 可辅助操作和检查，但 Linux/Xvfb 或伪装 Windows 的布局测试只证明该环境的 UI；Windows 安装、文件路径、原生对话框、解析资源和发布包必须在真实 Windows 目标机验收。多尺寸/点击命中检查集中验证联动、抽屉、反馈等实际变更。
4. **模型证据**：固定网关回复验证状态、引用、守门和并发，不验证真实理解准确率；真实模型按第 5 节使用锁定真值评测。`engine=ai` 不足以证明没回退，需记录实际渠道/模型、响应处理、模拟/确定计算来源和覆盖缺口；不用失败后的 fixture 输出当成功证据。
5. **结果留档**：每条记录 commit、构建/宿主平台、输入 manifest、模型配置来源、预期与实际、通过/失败/未执行及材料路径。历史演示记录不覆盖新改动，修复后重新执行相关路径；尚无校方接口的 S 保持未执行，C 的模拟验证独立留档。

完整交付必须同时满足 A/C 和相关 K 用例。M0 回归修复可以先证明不误判、不串案、不伪造，但不能据此将模板、OCR、审批、批次、助手或完整报告标为已完成。
