# G07-T07｜项目借款与事后冲账结清：独立业务深调研

> CDUT Studio｜G07-T07｜B阶段单模板深度调研 v0.1｜核验日 2026-10-12｜研究材料，非正式校规/生产规则/测试金标。

## 一、研究定位（B0）

**唯一审核目的**：核查因公项目暂借款的发起资格、借款用途与经费来源、审批责任和预期偿还/冲销安排；借款实际拨付后，继续核对具体费用冲账、余款返还、核销记录、延误或冲正，从而出具材料预审与风险提示。**同一套模板贯穿一笔借款的生命周期，不把“借款/还款/冲账/延期”拆成四套审核模板。**

上游A阶段统一目录的定义是“拨付前借款权限/用途审查及拨付后借款与票据冲销余额清算”，边界是仅形成预审结论，**不擅自放款、不替其他费用业务最终核销**。此次遵循此边界，并将A阶段校本补查结论作为输入，不默默认定旧流程仍全部有效。

**基线文件实际读取状况**：已读取用户上传的 `02_B_单模板深度调研_分支会话.md`，通过Library检索到 `G07_02_统一模板目录与边界.md` 及 `G07_07_成都理工大学校本规则专项核验.md` 摘录。**A阶段独立的 `G07-T07_研究交接卡.md` 未在当前会话挂载，Library定向搜索未定位到该文件正文**；A阶段原文摘要（差旅预借/竞赛对公预借/会议预借/项目预付款与冲销，以及CD10、CD13、CD14等证据线索）可以从已检索的目录追溯。后续若交接卡重新提供，应逐项核对，不把“读过交接卡全文”写成已完成事实。

## 二、成都理工大学校本证据（B1，本次独立重新查证）

### 2.1 借款责任主体——明确有历史校规依据

[L02] 成都理工大学2017官方《网上预约报账相关问题》第12、16、17问指出：**借款人只能是学校在职职工，学生不能作为借款人，但教师可委托学生在旧网报系统录入，由学生填借款教师工号**；负责人本人借款时，负责人签字栏须由项目其他负责人或单位领导签名；未冲销借款及核销号可由个人借款查询获得。这是对“申报账号”和“实际借款责任人”分离的**直接本校证据**。

注意2017属**历史系统**。2026智能报销已经替换旧入口（[L04]），当前不能强迫学生在新版系统输入2017字段名，也不能仅凭该FAQ就断言2022借款制度之后完全没有角色变化；**2022制度全文尚需核验**[L05]。因此C阶段可保留“学生不能自动当借款责任人”的角色校验，数值及最新权责作为校本配置，D阶段对“学生代录而老师承担借款责任”必须有合格对照。

### 2.2 五种借款用途明确有校本官方材料清单

[L01] 2025年4月财务《只跑一次财务事项清单》**第11张PDF页（印刷页码9），第20项**分别列：

1. **国内差旅费借款**：《成都理工大学国内差旅费审批表》或《成都理工大学科研出差审批表》；历史清单要求**借款金额大于50000元**附经费负责人签字的开支明细，注意“大于”与“含”不同。
2. **实习费借款**：《成都理工大学实习经费事前审批表》。
3. **版面费借款**：文章录用通知。
4. **国际差旅借款**：出国经费协议书、关于借款事项的说明（经办人、经费负责人及国际合作交流处审批）。
5. **其他借款**：合同、协议或付款通知等，可以是合法替代组合，**不是三份都必须提交**。

这里恰好表明“因公项目借款”有一套共同目的，但**缺件应按用途分支触发**。在国际差旅，不可仅因没有国内差旅审批表驳回；在普通版面费借款，也不可要求实习审批表。A阶段原文字段整理可以被L01直接验证。

### 2.3 实际还款与冲账路径

[L01] **第16张PDF页（印刷页码13—14）**：“现金退还事项”先将资金汇入学校账户，截图/打印回单；智能报销栏目选择“现金还款”，再选择待冲借款完成相关提交。旧网报系统另有勾选原借款、“现金还借款”和预约单、汇款凭单、经负责人审批说明的流程。**财务实际到账、账务已冲销必须由财务记录确认**，不能让上传截图自动标记为已结清。

**范围排除**：2025清单另有“非科研预借增值税票/预借财政票据”，属于**预开票与应收款管理**，不应因同有“预借”字样而纳入项目资金借款T07。[L01]

### 2.4 2026操作渠道版本冲突与解法

2026-01-13通知[L04]规定2026开账起原则上不再使用旧网上预约报销系统，转用智能报销。因此历史的“打印旧预约单、纸质窗口投递、3/4天”等操作不宜成为2026硬性必需材料。**2025清单已经出现“智能报销现金还款”操作，说明线上和旧网报曾并行**。目前无本校可验证的2026版借款页面字段表及2022正式《借款管理办法》全文。[L05]

2025年终通知[L06]含特定年度借款受理截止日；不得推广为每年统一日期。2017历史欠款清理[L07]只用来证明学校存在逾期治理制度及单位责任；不得据此新增现行工资扣除/冻结算法。

## 四、职责与权力矩阵（B3）

| 主体 | 可以形成的事实或操作 | 不可自然拥有的权力 |
|---|---|---|
| 登录用户、填报人、学生受托者 | 录入、上传、关联经费项目、补充说明 | 不因录入成功而成为法律或财务上的借款人；不能代替本人签字 |
| 借款责任教职工 | 申请借款、真实确认用途、按时清账、说明异常 | 不可用本人身份同时完成上级/独立审批 |
| 经费负责人/院系负责人 | 核准与项目相关性、用途与预算责任 | 不能以私人聊天替代OA正式审批，也不能宣称已拨款 |
| 财务会计核算中心 | 检验借款与费用账务凭证、实际冲销 | 专业采购/技术验收不由该模型或经办人自证 |
| 资金结算中心/银行 | 划付、收款、到账回单、交易状态 | 只看银行回单不能判全部费用可报销 |
| 费用审查责任部门 | 对T01/T02/T04/T06的具体费用进行合法性核验 | 不直接改变原债务责任人或捏造已冲销凭证 |
| 其他申请相关人（出差者、实习学生、供应商） | 能证明活动、旅程、交付或收费义务 | 无需与借款责任人强制为同一个人 |

必须至少保留**四个不同主体ID**：`form_filler`（填报人）、`borrower`（真实借款人）、`project_controller`（预算负责人）、`payee`（资金收款人）。审批人还要与借款人利益冲突校验。2017 CDUT FAQ第12题明确负责人本人借款由其他负责人/单位领导审批。[L02]

## 五、完整生命周期与独立输出

1. 事前活动/预算已有依据 → 填报人选项目与用途 → 验证借款主体资格、预算和过往欠款 → 按用途提交材料 → 负责人/有权人员审批 → 财务审核 → **实际拨付**（有银行凭证才能建立已拨债务）。
2. 活动或交易发生 → 费种T01/T02/T04/T06分别检查发票、行程、合同、验收 → 在冲账单中**明确关联借款编号和金额** → 财务复核/过账。
3. 业务取消/节约 → 退回余款（银行转出）→ 财务确认到账 → 将到账与借款配对入账；**转账截图不直接等于结清**。
4. 逾期/异常 → 结合该校规则从放款日或业务结束日计起、延期批复、催还冻结记录 → 若取得了合格审批只标记延期事实，最终执行由有权部门决定。
5. 错账/冲正 → 原冲账凭证关联冲正记录，重算未结余额，保留版本，禁止覆盖历史已支付数据。

核心金额勾稽建议（**研究推导，非任何学校硬规则公式**）：

`实际未结借款余额 = 实际已拨借款本金 - 累计已生效费用冲账额 - 累计已入账现金/银行归还额 + 累计已冲销记录的会计冲正额`。其中“退票”“第三方退款”需按已形成会计凭证的实际方向记录，不能机械把任何退款消息都当作债务已偿还。

对于本次借款与账务动作要分开输出：`材料是否充分/资格及风险/拟冲账额/待财务核验余额/实际支付状态`。申请人要求冲账 2万元，只能证明“提出申请”，不是会计记录已经减少2万元。

## 六、适用性及范围排除

- **在范围内**：申请新借款、差旅/实习/版面/国际/其他预借、原借款用途变更、借款凭票冲账、现金/银行归还、部分冲账和余款处理、延期申请、历史欠款核对。
- **按条件进入相邻模块**：外事出行批准（G05）、科研项目预算变更（教师T03）、商品采购批准（G07-T03）、采购合同履约（G07-T04）、直接活动费（T01）、差旅费（T02）、会议培训主办费（T06）。T07读取其**已完成或待完成状态**，不是替其审批。
- **排除**：生源地助学贷款、学费缓缴、教师个人因私借钱、学校预借税务发票、银行信用贷款、无账务借款关系的个人垫付报销、对供应商正常合同直接付款且不产生借款余额的情形。

## 七、重大风险与证据限制

- 误杀：学生代录正常教师借款、费用发生之前要求冲账票据、学校对公付款时强迫个人付款截图、合法延期却判逾期、一次报销部分冲多笔借款时认为重复。
- 漏放：学生本人当借款责任人、借款人自批、无预算/重复抵充、无财务到账却显示已结清、用无关费用抵借、已退票仍全额抵借。
- 权限与隐私：保存凭证引用或脱敏账户令牌，不泄露银行卡号及财务往来；“官方银行流水截图”仍不等于获授权获取的财务入账台账。
- 当前缺口：2022本校借款制度全文、2026新版借款角色/审批流程、实际借款期限、延期主体、外币付款、借款责任人替代情形。见05缺口文件。

## 八、研究阶段总结

业务目的独立且真实，资料足以形成 C/D 的同一事实基线；但未获CDUT 2022制度全文和2026后台规则，不允许将外校金额/期限当本校拒绝阈值。**建议：`READY_WITH_CONFIG_GAPS`**。后续C与D各自独立，只能采用明确的校本规则配置或合成规则配置，不能提前把未知项设为拒绝条件。
