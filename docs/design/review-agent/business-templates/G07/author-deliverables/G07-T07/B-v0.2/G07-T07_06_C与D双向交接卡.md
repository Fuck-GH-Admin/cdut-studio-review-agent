## 2. C阶段任务指令（不在此轮执行）

1. **一套模板、多个内部动作**：借款预审、委托发起、已借凭票冲账、银行归还、混合抵借+还款、延期和逾期清理、撤回冲正；不能因为有不同系统和附件就变成多个模板。
2. **按阶段与业务用途触发材料**：国内/科研差旅、实习、版面费、国际出行、其他合同或付费通知；未拨款阶段不要求报销票据、还款凭据；现金归还不能只看截图直接写已清账。
3. **角色模型**：`initiator / agent / borrower / beneficiary / project_lead / approver / accountant / bank_payer`必须能表达差异，至少不能把学生借款人和代理学生的资格混淆。
4. **规则参数化**：`school_policy_version`, `borrower_eligible_roles`, `max_loan`, `detail_threshold`, `settlement_deadline_by_use`, `deferment_approval`, `pre_clearance_requirements`, `approval_chain`, `fund_type`, `currency_rules`。没有CDUT2022原文，**不得启用缺失的校本数值硬拒规则**。
5. **输出层级**：材料受理/补正、基于可信事实的风险、待有权审批、已核准不等于资金拨款、拟冲账不等于会计已冲、银行已转出不等于财务已到账、整笔/部分清账分开。
6. 为每个规则标记来源ID、事件日期、适用范围、现行制度有效性、证明字段、替代证据与授权核验条件。42条候选不得未经审计整体机械入库。
7. 预借发票、学生助学贷款、教师个人工资预支等同名不同义办理事项必须排除或转给其他业务。

## 3. D阶段任务指令（不在此轮执行）

1. **独立的合成学校规则**：如果缺少CDUT现行借款办法全文，建立一套明示“虚构”的完整借款、审批、冲账与期限规则，用于闭合金标；另做多校差异的参数化切换。不能假借CDUT名义赋予外校处罚条款。
2. **测试集结构**：`01_审核依据`；`02_学生或教师提交/01_申报材料`、`02_申报事项`、`03_证明材料`；**另一个独立的授权财务底账快照**；`golden_answer`必须与输入物理隔离。
3. 必须包含：正常借款、学生合法代录/无权本人借款、等号金额边界、五种用途条件附件、对公付款/个人付款、首次借款/既往欠款/有效延期、资金已拨但无账票、未拨状态、部分抵借、重复报销、一借多票/一票多借、现金转出但学校未到账、退款/冲正、政策版更替、不同费用审批阶段、校本规则未知、OCR受损而仍合法等对照。
4. 扫描纸质借款表、银行回单、发票等**先渲染成图片再嵌入PDF**，避免直接文本提取绕过图像识别；真实数字平台生成的电子凭证允许保留文本层。
5. 所有设计者写的“这页缺章”“与另一页金额不同”“重复票据”“预期不通过”等，**只进入golden_answer，不得以文件名、页眉、报告批注泄漏到输入**。
6. 金标按 `borrow_id + expense_line_id + offset_amount` 给分项结论与复核状态，并明确审批/支付完成与否；不要只给单个布尔审批结果。测误杀、漏放、资料缺项、政策版本、人员权限与部分金额准确率。
7. 对接真实学校内部系统不可用时，不得把“无法验证余额”默认为“已欠款”或“无需查”；可向测试环境注入虚构且一致的校方账簿快照作为唯一权威事实源。

## 4. 不能跨越的责任边界

- **G07-T01/T02/T04/T06** 仍然分别决定直接费用、差旅、合同付款、主办会议费是否合法；T07只核借款与已确认有效费用之间的抵借清算。
- 差旅出国批准G05、经费预算正式调整或用印合同审批、学生资助贷款等由相邻业务完成；T07引用批准记录，不重签发新审批。
- 专业会计过账、税务核验、银行实际支付、薪资追索属于授权部门系统执行，不属于通用审核模板的自动动作。

## 5. 已明确和未闭合的核心事实

- **可确定的现象**：成都理工2025清单的五种用途和借款材料、2017FAQ的学生代录与教工借款责任，2026原则转智能报销，账款冲销与真实银行付款属于不同阶段。[L01][L02][L04]

- **可适用的通用事实关系**：需有正当经费用途、具备有权主体/预算、付款后才能成立债务、抵借须关联有效费用、实际还款和会计清账不得由截图替代。具体处罚和数字阈值绝不跨校外推。
