# G07-T07｜候选审核规则与权限边界

> CDUT Studio｜G07-T07｜B阶段单模板深度调研 v0.1｜核验日 2026-10-12｜研究材料，非正式校规/生产规则/测试金标。

## 0. 使用规则的前提

这是**候选审核事实与条件研究**，不是 C 阶段的最终规则表，也不是可直接上线的JSON。`本校明确`与`外校借鉴`必须分开：L01和L02中规则可作为历史成都理工大学业务证据，L04覆盖其2026操作版本；所有期限、借款等级、出借权限等若无2022本校《借款管理办法》全文，**不能把E01—E14其他高校条款当成成都理工大学的正式拒件规则**。

按可自动化程度分层：**客观材料一致性**（如主体、金额、类别、版本）可以机器预审；**需有权系统**（预算余额、欠款、资金到账、发票状态）必须读取可验证台账；**有权批准/处罚**（自审回避、延期、冻结、财务划款、核销坏账）保留原审批岗位执行。

## 2. 候选审核动作的权限等级

| 等级 | 行为 | 系统能够输出什么 | 不可擅自做的事 |
|---|---|---|---|
| C0 文档级 | OCR、日期/金额提取、证明关系、材料缺口识别 | `material_precheck` + 页码和匹配关系 | 不可基于图片认定真实银行到账 |
| C1 校内只读数据级 | 预算、已借账、审批是否真实存在、银行到款、会计销账 | `needs_external_verification` 或通过可信校内事实核查 | 不可向无关学生公开老师全部借款情况 |
| C2 有权审批 | 项目负责人/单位审批、延期、用途变更、财务会计核准 | 转有权岗位签署或待审批 | AI预审不等于批准借款、延期或抵账 |
| C3 资金与会计执行 | 银行划款、退款、会计凭证、冻结/解冻 | 读取成功或失败事件，更新只读业务状态 | AI不得模拟已放款、已冲账或自动扣薪 |

## 3. 关键公式研究（示意，并非可执行金标）

- 以会计生效数据而非申报表为准：`余额 = 已拨本金 - 有效抵借账金额 - 已确认学校到账还款 + 有效冲正增加额`。
- 对任意`borrow_id`：`0 ≤ 累计生效抵借 + 本次拟抵借 ≤ 账面未清本金`。冲正应建立相应反向凭证而不是覆盖原记录。
- 对任意`expense_line_id`：`Σ分配至各借款的金额 ≤ 同一费用行经费种业务核准的可冲账净额`，同一票号若被其他报销使用须由历史系统按业务ID判重。
- 现金还款已发起但银行尚未实际到账：`requested_return` 与 `confirmed_return` 必须分开，不可在申报材料里自创会计入账额。

## 4. B 阶段不能替C阶段作的决定

- 不将每个 42 条候选都转成一条硬必填审核规则；有的只能当系统检索、状态转换、人工裁量边界。
- 不预设“逾期三个月必冻结”“借款超过一万元必须校长审批”等为全国或CDUT现行硬规则。
- 不在没有学校授予权限的情况下做银行账号解析、自动支付、销账、扣薪、冻结或修改原始凭证。
- 不以‘材料齐全’就写‘已批准’；更不能仅凭一张汇款单说‘已归还’。
