# G07-T03｜与D阶段独立测试作者对接说明 v0.1

> 只提供业务范围、公开规则、输入输出ID、状态语义和模型可观察前提；不读取、生成、传递D独立金标答案。

## 1. 唯一业务入口与边界

- 业务模板`G07-T03`：物资与服务采购**事前**经费合规预审，不是活动报销或采购履约/付款。
- 一案多包，应能区分货物/服务/工程分流、政府采购/非政采、统一/自主/框架、纵向预算制/横向包干、科研急需、进口、单一来源及修订。
- 审核系统只能引用校方正式批准事件；其自己的“材料已核对”不是授权采购的最终批准。

## 2. 供D使用的公开ID

- 字段 `F-01…F-42`；材料槽 `M-01…M-25`；规则 `R-01…R-33`；分支 `BR-01…BR-14`；阶段 `ST-00…ST-06`；证据组 `EV-01…EV-09`。
- 官方来源 `CD01…CD19`（B版本检索状态见来源登记）、上位`MOF01/SC01/LAW01/MOE01/MOE02`、外校`EX01…EX07`。
- 规则问题码以主母版每条 `ISS-R-xx` / code_name 为准；多条并存不得只返回一个总故障。

## 3. 给D的可测语义而不是测试答案

|主题|合法可核事实|必须避免的错误解释|
|---|---|---|
|阶段|事前草稿只需本期合法事实|索要未发生的中标/合同/验收/发票|
|政策|按法/校规生效日与资金范围选适用规则|外校严规套CDUT；UNKNOWN→宽松路径|
|资金|纵向设备费调增/调减不同职能审批，横向包干无逐项预算|一律只查项目负责人或一律要求科目预算|
|急需|科研设备耗材可走CD12候选免招标路线|“急需”自动免全部学校采购手续|
|角色|申请人/经办/项目负责人/采购批准人可不同|学生填写需求自动等于负责人审批|
|资料|等价证据组和校方R记录合法覆盖上传缺项|要求每种纸质截图都必须存在|
|多包|各包独立材料、预算及条件|一包有缺口强制整个项目否决|
|专业判定|法律采购方式、供应唯一性、重大设备等需专业权责|AI凭PDF文本自我签字批准|

## 4. D环境约束与输入防泄漏

1. 可基于本母版及B来源设计**虚构但完整自洽的学校制度**，把法律、校规、生效日期、角色权限和特定金额明确写成待审核模型可见的规则文件。不得声称模拟金额即真实CDUT标准。
2. D自行构建采购需求、预算台账、OA审批/权限、需求论证草案和阶段材料；项目文件引用归属必须精确到采购包。
3. 纸质专家签字页、审批章、采购需求扫描表应先成图再嵌入PDF，确保扫描文书无可直接提取的文本层；真实电子表格/网页可保留结构。
4. **申请输入不得泄露异常答案**：文件名/页眉/正文不能写“此处缺预算”“审批人无权”等；评测缺陷与Gold独立隔离。
5. 需要系统底账时可构造专用模拟只读API响应/数据库快照，并明确模型能访问的范围；不可用时正确答案可能是`external_unavailable`，不要只从附件猜真伪。
6. D必须独立产生期望结果、拒绝逻辑、金额、证据定位和误杀/漏放评分；C作者的文字走查只是自检，不当成独立金标。
7. 评测应分角色/阶段/包、来源追踪、漏放/误杀/过度人工复核、对合法例外的处理；批准/已付款状态必须与模拟OA/财务权威记录一致。

## 5. 源资料未闭合项，D应怎样隔离

- 校本U01/U02/U03/U04/U12未关闭，若模拟严格业务规则应在虚构政策中**显式制定**并标虚构，避免把未验证CDUT规则塞进金标。
- D不得以“模型没拿到登录权限”为由创造一条学生应主动提交官方预算截图的规则，除非模拟制度和实际案卷赋权流程明确。
- D与C之间共享的是稳定业务合同，不共享D的独立真实案卷结果和隐藏金标。
