## 0. 结论与适用边界

**唯一审核目的**：对某一科研项目、某一发放批次的**每名拟受款人在指定工作/咨询期间**的人员类别、适用项目、劳务或咨询事实、适用额度、身份/付款账户、相关审批与历史发放，提供可追溯的**材料预审**，输出逐人逐项的资料状态、初步可发额/待核额与应转有权部门的事项；**不替人事、财务、导师和银行正式签批或执行资金支付**。[A01][A02][A03][B01][B02]

从A阶段保留 `G07-T05` 一个模板，**内部按人员与资金制度分支**，不因为都涉及`project_id`/`person_id`/`amount`就套相同证明文件。本研究对A阶段增加两项重要修订：

1. 本校2025《“只跑一次”财务事项清单》将“科研技术成本费、纵向科研绩效、横向结余科研绩效”列为同一**财务酬金操作大类**，但这不证明它们与助研、外聘专家拥有相同**实质授权和资格**。对涉及教师绩效分配的申请，本模板只做**归类与已有批准附件完整性校验**，实质分配/考核应转教师岗位绩效或科研项目专门审批（邻接T02/T03）；不可因旧清单写“横向结余无需附件”就推断所有审核环节皆豁免。[A01][A02]
2. 本校2026年智能报销已原则上取代旧网上预约系统；2026年还特别发布了**经费负责人本人领取酬金需要部门领导互签**的操作须知。旧流程的“打印旧预约单、投递”不是所有2026新申请必需材料；“负责人本人受款”须独立权限检查。[A03][A04]

### 0.1 四类责任边界

| 人/机构 | 本模板真实角色 | 不得推定的权限 |
|---|---|---|
| 劳务领取人：本科生、硕博、校外临聘、访问学者、专家 | 被核资格及收款人；部分聘用制需本人确认协议 | 学生领取≠学生可自行审批经费；专家本人写意见≠财务审批 |
| 经办/预约人：导师团队助理、授权学生、工作人员 | 准备发放单、录入信息、上传证据 | 填报≠项目负责人签批；学生能否作为正式系统经办人由校本角色权限决定 |
| 项目负责人/导师及学院 | 核任务/工作量、合理性、预算、人员名单，按权限签审 | 自己受款时不因此可以独自完成全部批准；部门领导互签条件需核[A04] |
| 学工/研究生院/科研/人事/财务及银行 | 各依学校方案核验资格、考核、工资及税务，形成批准和执行 | 模型通过不等于院系批准、财务已制单或银行到账 |

## 1. 本校已经确认的可审事实

### 1.1 2024标准流程（历史办事指南，不等于2026技术操作）

成都理工大学财务处《科研经费-酬金发放事项标准流程》（2024-04-19）将下列支出分开列附件：[A02]

| 酬金业务 | 校内公开要求（对应当年流程） | 建模影响 |
|---|---|---|
| 助研津贴 | 自制《工作量统计表》，项目负责人审签 | 任务/工作量与批准是主证据；不能要求每名学生交购买发票 |
| 科研技术成本费 | 新项目A/BH开头无附件，旧如SH项目上传《科研项目酬金发放审批表》 | **项目编码规则具有年份、资金来源及系统上下文**，绝不可按前缀硬编码到2026 |
| 科研财务助理等劳务 | 五方协议；校外人员发放附《工作量统计表》 | 协议和实际工作记录是不同证据；校外人员先维护信息 |
| 纵向科研绩效 | 《科研绩效考核报告》《绩效分配方案》 | 属跨岗位实质分配审批，需另有审批结果；只能在T05校验附件 |
| 横向结余科研绩效 | 该2024旧流程记“无需上传附件” | 不能推导“2026不需绩效方案/不需项目结余审核” |
| 专家咨询费 | 《专家咨询费发放审批表》 | 专家咨询事实、专家身份和禁付范围另外核查 |

财务清单第19项另明确：**校外人员先信息维护；银行上卡与现金发放两种方式不得混在同一酬金预约单；学生助研工作内容是必填项；付款失败另用银行退款重转申请单。**其中“银行上卡/现金”是**2025材料的历史操作路径**，2026采用何种账户/现金例外尚未核定。[A01]

### 1.2 2026运行事实（比2024流程更新）

## 3. 条件类型与合法替代的总体原则

1. **助研任务证明可因学校制度不同为自制工作量表、系统导师考核、协议内工作任务记录；只需要实际事实充分且签审完成，不要求固定文件名。**CDUT旧流程明确自制工作量表。[A01]
2. **临时科研劳务与专家咨询不同**：课题组实际执行任务可申科研劳务；同项目参与管理者不能借专家咨询名义领取受相关资金规则禁止的专家费；必须先判断支出来源及具体资金办法。[N01][N02]
3. **一份批次申请有多位收款人、多种状态**：姓名/学籍已核的行可有条件通过材料审查，另有缺工作量或银行卡未绑定的行待补；是否允许拆单部分批准由财务政策/系统配置决定，不能仅因一个人异常直接判整个批次无效。
4. **不同身份重复同月**：可存在真实不同项目和不重叠工作。仅“同名+同月”不证明虚报；同一`person + project + task + period + work evidence`被重复申报才需严查。[B01][B04]
5. **银行退汇与审批否决不同**：原发放批次可能已经核准但银行退回，需匹配原流水和退回凭据再重转，不应再次凭同一劳动生成全额新收入。[A01][A06]
6. **机密字段最小化**：公开审核解释只显示脱敏身份和关联ID；真实学籍、人事、银行、税务状态通过受限接口匹配，不索要或传播真实账号全号。[A05][N01]

## 4. 生命周期与部门责任

`发放准备/预算校验 → 逐人选择收款类别、填申报单 → 上传条件证明/人员确认(如有) → 经办及项目负责人核验 → 学院/专项部门审批(视类型) → 财务会计/税务核算 → 银行发放 → 成功/退汇/重新支付 → 归档或撤销追溯`。

| 业务阶段 | 预审能够确认 | 预审不得冒充 |
|---|---|---|
| 准备、提交 | 项目编码、类别、人员、拟发金额和应提供附件是否齐备 | 批准资格、工薪入账 |
| 学籍/协议/工作量核验 | 可见材料内事实、可信系统返回的身份与工作期限 | 导师已经批准/学院已签字（若状态仍待办） |
| 部门审核 | 有权审批人及真实电子签记录、利益冲突互签节点 | AI替部门领导给自身审批 |
| 财务核算 | 能对照预算余额、会计/税务系统回显的毛额、税额 | 从一张报表估算并声称法定实际扣税完成 |
| 银行发放 | 能读银行成功回执、退汇状态、原支付流水号 | 把“已提交银行”当“已到账” |

## 5. 本研究暂保留的边界争议

- **科研技术成本费**：CDUT将其放酬金办理菜单，但受益身份与成本形成机制不清。暂在T05做**类别识别+校本材料完整性及历史流程兼容**，本体科目资格审查转项目资金规则，不能将其等同研究生助研劳务。
- **教师科研绩效**：旧校财务同一发放菜单，然而实质上是科研绩效薪酬分配，和学生工作量劳务分属不同责任链。T05应仅识别及转交已成立绩效审批链；不得因为菜单共用而合并最终权限。
- **科研项目外的事业劳务、学生勤工助学、奖助学金**：旧第19项同一个栏目，不代表G07-T05业务本身涵盖它们。根据经费源/申请目的流向事业经费或学生S03勤工/资助的专属审核。跨出本模板时应提供路由建议，而不是申请人有罪式“驳回”。
