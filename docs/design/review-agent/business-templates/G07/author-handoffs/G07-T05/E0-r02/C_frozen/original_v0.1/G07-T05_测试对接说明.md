# G07-T05｜D阶段独立交叉验收接口说明（C作者提供）

> **隔离协议**：本文件只是稳定规则ID、业务边界和输出语义，D应独立制作依据、材料和隐藏金标，不能用作者的自检走查作为验收答案。作者不得获得D内部Gold和用例。

## 1. D应引用的固定合同

- 模板 `G07-T05`，作者母版 `MD@0.1.0`，当前仅`BUSINESS_MD_DRAFT_WITH_GAPS`。
- 输入四层：申报事项/申报材料/证明材料/可信权威记录（后者需权限或仿真受控底账）。
- 单位：`batch_id`→`line_id`→`recipient + project + task + work_period + action_id`。
- 条件维度 `BR-01..15`；字段 `F-01..58`；材料 `M-01..29`；等效证据 `EV-01..09`；审核原子规则 `R-01..45`；审核阶段 `ST-01..09`。
- 输出必须区分`materials_state`、`review_recommendation`、`authority_decision`、`payment_state`、逐行问题码/证据/金额初判；已知权限缺失和未发生付款必须是显式状态。

## 3. D不能默认的前提

- 成都理工大学一般助研月额、一般专家标准、临聘合同门槛、2026智能表单列名尚未校本确认。金额边界应在D自行固定**自洽可判且明确的虚构校规**（如选择模拟模式）；不能宣称外校标准是CDUT规则。
- A13专项真实规则只有`80303-FZ11200+相应科发院活动`时适用。单纯“专家费”不是其条件。
- 受限学籍/预算/发薪/税务/银行原始数据不可由申请人自述代替；D可在独立环境构造可信底账，但测试输入和Gold必须隔离。
- 专家税后标准不等于实际个人税额；“已审批”与“银行到账”完全不同。
- 纸质扫描证据在测试制作时应先渲染成图片再嵌PDF，验证`page.get_text()`无文本层；校园原生电子表单、Excel、OA导出则按其真实格式。

## 4. 反馈格式建议

D只需将被证实的**公开失败描述**传回C：`rule_id / 适用分支与资金版本 / 失败类型(误杀/漏放/错误待核/越权/信息泄露) / 证据类别 / 期望业务语义 / 需要修订的章节`；不要传回隐藏金标全量答案，C只针对失败责任改修并重新做作者静态自检。

## 5. 验收责任划分

- C: 业务MD含完整条件、证据、权限、输出语义和自检记录。
- D: 独立构造盲测、金标与评测器，并根据可证失败提出修订建议。
- 产品/学校: 发布门控、现行政策授权、权责审批/财务和银行执行。C与D均不替学校批准酬金。
