## 4. 完整性与过度机械审计（实际修订记录）

| 问题 | 初始风险 | 已修订后的做法 |
|---|---|---|
| 只用姓名/月判重 | 两项目不同任务被误杀 | 引入`recipient + project + task + work period + source evidence`，外部台账辅助 |
| 把助研和专家混一个金额公式 | 税前后、工时、半天、通讯不同 | 根据受款角色/工作方式/资金制度分别核算 |
| 因材料没出现“签名”就拒绝 | 未到签批阶段和学生尚未确认协议 | `not_yet_generated`与`missing_required_document`分别报 |
| 校本表单不可下载 | 根据通用惯例自行补造表头 | 只写已证栏目及拟审字段，明确缺失 |
| 看到旧目录有教师绩效 | 自动把教职工薪酬当学生劳务 | 类型分流并只读取实质绩效审批结果 |
| 同批多个收款人 | 只出一个通过/驳回 | 逐人判资料完整性，拆批支付由财务决定 |
| 看到账户更换 | 公开银行卡和证件 | 验证后台绑定状态、输出只给脱敏标识 |
| PDF纸章和手写签名 | 视觉伪造难辨 | 先校验数字签与授权数据，无法核查转复核 |
| 政策只找到外校 | “越严格越好”强制全校 | 只借鉴例外和字段维度，金额及门槛按适用学校版本 |
| 主管已否决 | 只检查材料就给通过 | 真实审批拒绝优于模型建议，不复活审批 |

## 5. 质量检查结果及阶段判断

- 核心业务目的、责任人、独立审查对象：**已研究**；但学生可以直接经办CDUT平台的精确权限为校本配置。
- 所有发现的真实大类：助研、科研财务助理、校外临聘、专家咨询、旧科研技术成本费/纵横绩效交界：**已覆盖**；后两者需跨模板接口。
- 申报事项/申报材料/证明材料/底账：**已分别建模**；不对一切人员强制全部24槽。
- 生命周期：**已覆盖**；没有将银行回执设为提交阶段必交。
- 合法替代和人工权责：**已覆盖**；为通讯专家、合法补发、账户更新、本人互签、外籍特殊路径保留条件分支。
- 双向反事实：**28类**，包括正常、条件不适用、缺件、替代、冲突、低可信、未成形、否决、越权、校本未知、复合异常和逐行分化。
- 完整校本2026收入金额、全部实际电子表单：**没有取得**；不影响研究完成，但**会阻断以真实CDUT名义固定金额和审批权限**。
