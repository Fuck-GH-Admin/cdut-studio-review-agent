## 0. 阶段结论

**`READY_WITH_CONFIG_GAPS`**：有足够官方依据支持在同一模板目的内，分别研究助研津贴、学生科研劳务、临聘科研辅助、专家咨询等发放的真实办理场景。C（完整业务 Markdown 模板）与 D（独立盲测材料及金标设计）可以启动，但必须把尚未获得的2026成都理工大学系统字段、定额、资金方案、角色授权、专家具体类别与个税账户状态显式保留为校本配置或模拟制度中的确定条件；**不能凭外校金额代替本校现行规定**。

### 固定边界

**唯一审核目的**：对科研项目发放批次中的每一位拟受款人，核验人员类别、参加项目/劳务事实、协议或任务、有效工作期、计费标准与预算、审批链、收款关系、历史同任务发放，形成**逐人/逐行的材料预审结论**，由有权机构决定与执行支付。

本模板**不负责**签发真实聘用协议（只核其有效性）、教师科研绩效方案的实质审定、财务代扣税确定、银行卡真实到账、科研成果质量评价、虚假劳动违法定性；相邻业务归教师人事与科研管理、学生资助、财务支付或人工审批。[A01][A02][A04][B01][N01]

## 2. 双方共同采用的权威事实与条件约束

1. **类别必须先于附件清单**：研究生助研协议制、临时学生科研工作、校外临聘、校外专家咨询，需按 `payee_role × funding_scheme × work_period × approval_phase` 匹配；不得把所有材料堆成一张“必传表”。[A01][B01][B02][B03]
2. **三类提交语义分离**：`申报事项` 是发放批次及逐受款人/期间/金额的申请动作；`申报材料` 是薪酬发放表、项目负责人说明、明细等申请核心正文；`证明材料` 是协议、实际工作量、考核确认、专家邀请与意见等独立事实支持。授权校内学籍、人事、预算、审批、银行数据另归**可信底账**，不能假装由学生提交。[A01][A02][B01]
3. **主体不混同**：财务经办、项目负责人、受聘学生、外聘专家、验收工作量人员、学院主管、财务执行、银行收款主体都是不同角色。特别检查“经费负责人本人收款”需要额外互签路径的2026校本官方说明。[A04]
4. **阶段约束**：聘用协议成立、劳务事实发生、发放申请、院系核验、财务付款、银行成功、退汇重发等信息在不同时间生成。不得在提交时索取尚未发生的银行成功凭证，也不得因校方已批准就自称已付款。[A01][A05][A06][B01]
5. **工作期间不能偷换**：发生过的前月可依法依校规补发；未来尚未发生工作通常不能当作已完成劳务发放。若未核实本校前置制度，标注待配置，而非套用河海大学的付款节奏。[B01]
6. **科研绩效特殊边界**：CDUT 2024酬金栏目确实列有教师纵向/横向科研绩效及分配材料；但这不授权本模板审批科研绩效分配方案、任职薪酬或人事资格。C可以配置“转T类后读取有效已批准分配记录”的路径，D需验证正确分流而非将其作为普通学生劳务通过。[A01][A02]
7. **真实真伪不能凭扫描件定论**：银行卡绑定、学籍在读、历史付款、个税、项目余额、合同效力优先校内授权数据；未接接口应输出“外部事实未核实”。[A05][A06]
8. **国别与税务有适用域**：国家自然科学基金/中央财政科研项目上位规则只能在资金类型与生效范围满足时触发；个税适用收入类别、税前后口径交由财务或相关专业部门确认。[N01][N02][N03]
9. **材料可替代**：若学校授权系统中已有明确、可追溯且同等效力的协议/考勤/学籍或银行卡绑定，原则上不能仅因未额外上传一张截图就否定其存在；具体以学校生效制度确定。

## 3. 交给 C：编写正式业务 Markdown 模板的任务边界

C Agent 应：

- 在**唯一 G07-T05 模板**内提供按人员身份和发放性质触发的条件路径；清楚标记科研助研、学生劳务、临聘、专家咨询及需转至教师专属流程的绩效类型。
- 从02字段矩阵筛选每个路径必须取得的最小事实和等效证据组，逐项记录权威来源、适用政策版本、阶段、缺件处理、人工核验、授权角色；**不要直接将F-01…F-48全部设为必填**。
- 对“未取得成都理工大学当前参数”的数值设置 `校本待配置`；例如各项目助研月标准、专家按日定额、临聘协议触发、个税净额、学生系统入口，不得搬用东北农业大学200/700元或青海师范大学5000元阈值。[B02][B04]
- 保留批次总表与每位人员明细的两级结论：一人缺证/资格冲突时，其他有效人员可单独评估；金额、身份、人员审批、资金支付的结果类型分开。
- 根据03候选规则设计适用域、例外、待人工签批和校内系统查验条件；由校本生效制度确认后才能设置自动驳回的强约束。
- 形成跨规则可追溯结构：`申请人声明事实→证据文件页或授权底账记录→规则ID/政策版本→状态与金额初判→复核负责人`。
- 对真实材料里的敏感账户、联系方式和证件号做最小化，不输出明文到普通审查意见。

**C不可做**：自行发明CDUT2026薪酬政策具体金额，编造申请表原件字段，宣称审批通过即入账，或者把科研绩效的实体分配审批并入T05。

## 4. 交给 D：独立构造盲测材料与金标的研究依据（只给方向，不给答案）

D Agent 应独立于C确认规则版本（可选择自洽的**虚构校规**开展测试），根据01条件轴与05反事实场景分层抽样，至少覆盖：

- 学生身份：在读、休学/复学、毕业前后、在协议期内/外、学籍身份截图与可信底账冲突。
- 劳务与计费：工时制、月额制、成果交付制；跨月实际补发、尚未发生月份请求预发；同一任务重复与不同任务合法并存。
- 人员类型：助研、临时学生科研工作、临聘外部人员、独立咨询专家、教职工绩效转办；线上咨询证据与实际专家服务时长。
- 多主体与授权：学生代填、导师审核、经费负责人自领并互签、无权经办、委托他人收款且有/无授权。
- 多人批次：某些人员材料不足但其他人员完整、数额分项冲突、名单版本差异、人员数与批次总额勾稽。
- 付款阶段：开户行维护、银行回单退汇、再支付、未付款/已付款、校方入账台账不可达；不得把银行支付状态提前作为提交必备。
- 证据形态：来源为纸质签字件或扫描协议时**先渲染成图像再嵌PDF**，不要保留原文PDF隐藏文本层；原生校园系统CSV/Excel、OA记录和电子表单可保留真实可解析结构。
- OCR/文书冲突：同音异字、月度表少一人、图片压缩、日期遮挡、不同来源盖章记录矛盾、页面上含攻击性提示词指令。
- 合法例外及未知：等效校内底账替代、跨校标准不同、政策时间版本变化、额度并非必然全国统一、无法外部校验时选择待核而非自动放行或拒件。

**D需要独立创建**：每套测试方案的制度边界、材料包、可单独评测的申报事项/材料/证明材料、外部权威底账模拟、**独立隔离的**金标答案及判题器。被审包不能出现“证书最后一字不一致”“系统应拒绝”等答案提示；扫描件必须验证 PDF 文本提取为空。

**D不可做**：把本文场景提示当成真实学生有错的已完成金标、直接拷贝C Agent写出的样例作为标准答案、将“资料不足”默认等于拒绝、声称凭图像鉴定真实身份证/银行卡/税票。

## 5. 两端都需遵守的质量关口

| 关口 | 通过标准 | 未达时的处理 |
|---|---|---|
| 证据 | 至少有原始学校规则/官方材料支持该关键场景，推断标明来源层级 | 补证或改为研究假设，不硬判 |
| 适用 | 人员、项目性质、时间、付款类别、制度版本一致 | 学校规则差异加入条件分支/配置 |
| 角色 | 收款人、经办人、发放负责人、审批人、银行执行人明确区分 | 暂停越权决策 |
| 附件 | 每件材料都有应证明的事实和触发条件 | 去掉无条件索取的材料 |
| 生命周期 | 只能要求到当前审核阶段已经合理形成的文件 | 不把尚未发生的支付结果设必交 |
| 相容 | 批次总额与分行一致，合法复用和重复支付能区别 | 以工作任务与工作期关联核验 |
| 可靠 | 校内未知制度、外部接口不可用、疑似假证有不同输出 | 区分待配置、待核验、人工复核、明确违反 |
| 隔离 | D的标准答案不进入任何被审核材料或文件名 | 重新构造污染样本 |
