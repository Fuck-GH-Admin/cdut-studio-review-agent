## 4. 业务入口和边界（供E独立交叉验证）

- **业务唯一目的**：在已形成的采购/订购/委托服务关系中，对具体付款动作和明细行作履约结算材料预审；不取代采购立项T03、正式验收、合同授权、人事薪酬或银行付款。
- **输入契约**：①`申报事项(case/payment_action/payable_line)`、②`申报材料`、③`证明材料`；外加**独立受限、经授权的可信底账**（采购、合同、资产、税务、财务、银行）。
- **主阶段互斥**：`BR-01`首款/预付、`BR-02`进度款、`BR-03`验收尾款、`BR-04`退款/冲账或质保处理按每付款动作择一；各行品类、涉外、内部转账、部分履约等条件叠加，有未知时不得默认进入最宽松分支。
- **预审边界**：采购前期未知、当前阶段尚未形成后续证据，应标记为尚未到期/待有权确认，不应机械退件；验收报告有效性由权责部门判定，系统不代签。
- **合法例外**：依法/合同/校规允许的预付、分批交付、内部结算、合同主体更名、合法委托及分期共用票据，均按触发条件而非文字同一性判断。

## 5. 输出语义与对照验收边界

- 对每个`payment_action`和`payable_line`分别输出：材料状态、证据状态、`R-ID`/`issue_code`、证据位置、未知原因、建议下一岗位、分项候选可证金额上限；全案聚合保留未解决阻断项。
- 区分`NOT_APPLICABLE`（未触发）、`NOT_YET_DUE`（阶段尚未形成）、`NEEDS_DOCUMENT`、`WAIT_EXTERNAL`、`WAIT_POLICY`、`WAIT_AUTHORITY`、`HUMAN_REVIEW`、`FORMAL_DENIAL`及材料可预审等状态，按母版完整输出定义解释。
- 账簿未接入时，不能断定发票有效/无效、预算余额或银行到账；候选可证金额≠正式批准付款金额。
- E可依据自己取得的C冻结候选和D独立材料/金标执行交叉验收；**C作者不得接触D隐藏案例与答案**，也不得在C中替E标记通过率。
- 如果E发现失效条款、证据不足、错杀合法预付或合同资金重复占用，应返回可复核的`R-ID + 事实输入 + 正确制度 + 实际冲突 + 建议修订`；C只有收到该类反馈后另开版本修订。
