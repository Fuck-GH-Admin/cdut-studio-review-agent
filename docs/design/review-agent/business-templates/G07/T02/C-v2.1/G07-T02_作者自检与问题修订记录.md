## 3. 发现的问题及本轮修订

- **FIX-01**：初始设计易把“所有补助规则必须已核才能保存客票判断”混淆为整个申请不受理。改为**独立事实识别 + 财务额度挂起**，允许票面一致但档次未核。
- **FIX-02**：B规则可信底账的`R-01`与原子规则`R-01`冲突。母版规定明确命名域（`B.R-01`是经费底账，`RULE.R-01`是业务路由）并新建`F-字段`映射。
- **FIX-03**：采购/会议主办/借款经常包含差旅发票，原型容易用文件名错误路由。改为按**申请目的/旅后个人费用**路由，混合费用分项。
- **FIX-04**：学生身份可能成为岗位负责人，但不能自动套职工等级；改为有效政策适用人群必须来源确定，未知金额`null`。
- **FIX-05**：合法免费住宿与实际支付房费但丢票不同。将EV-06与EV-07/EV-08分别建组，免费住宿房费0而交通独立核。
- **FIX-06**：住宿发票多张与酒店分摊可能重复报。加入`hotel_stay_id + share_id`和金额不超原始有效支出的不变量。
- **FIX-07**：外部接口无法核验被错误视为材料缺项。分为`EXTERNAL_UNVERIFIED`与`NEEDS_SUPPLEMENT`，后者仅对已确定用户应提交的文件。
- **FIX-08**：多系统审批“已提交”曾与“已批准”语义接近。独立`AuthorityState`，禁止AI写`FORMALLY_APPROVED/PAYMENT_PAID`。
- **FIX-09**：当前D2合成试点可映射多业务对象，但未覆盖本模板的复杂证据逻辑。把能力状态改为“已有代码/合成试点/未证”三层，不能直接发布。
- **FIX-10**：校本2024第七条搜索摘录确证有限。将野外替代写为有权部门复核且依据状态`P-text`；不宣称2026所有无票场景均可直接免票。
