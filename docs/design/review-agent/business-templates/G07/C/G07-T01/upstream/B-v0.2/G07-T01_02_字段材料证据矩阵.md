# G07-T01｜字段、材料、证据与等效证明矩阵（B阶段）

> 本文件与同目录的 `G07-T01_02_字段材料证据矩阵.csv` / `G07-T01_02_字段字典.csv` 同源。提供**材料槽M与字段F的稳定研究编号**。该编号仅为B阶段研究ID，**不是C阶段正式Schema字段ID，也不是D金标键值**。
>
> 原则：**每个字段都有触发谓词**；B基础、C条件必需、R可信校内底账或外部系统、O辅助、OUT仅输出。某材料同时满足两个事实时无需重复提交；核验事实不是强制上传清单。

## 0. 输入和权威事实严格分层

| 类型 | 准确定义 | 示例 | 为什么分离 |
|---|---|---|---|
| **申报事项** | 申请人要求学校完成的具体支付/核销动作及其费用行 | “申请某届赛报名费680元，费用行01，使用竞赛专项” | 一个活动可以有多个费用行，结果可部分成立 |
| **申报材料** | 申请人主动提交的核心报销文书 | 费用报销单、活动事项说明、缴费情况说明、纵向经费说明、票据遗失申请 | 这些是“申请方的主张与说明”，即使盖章也应核签批权限 |
| **证明材料** | 支撑上述事实的他方/单位证明 | 竞赛通知、发票、订单、付款凭据、正式名单、签领、论文录用通知、专利文书 | 可来自原生图片PDF/扫描件/邮件/OFD；需确定签发主体和法律效力 |
| **可信底账/接口** | 不向申请人强迫上传的学校或税务/银行记录 | 当前预算余额、历史核销、授权角色、发票红冲、财务支付状态 | 没权限或接口故障不代表申请违规，更不能让学生伪造系统回执 |
| **审核输出** | 只供流程执行参考的机器预审结论 | 逐费用行判断、需要补事实、待核验点与依据 | 不应回填到被审核的证据资料里 |

## 3. 跨文件核验关系图谱（允许多对多，不硬编码单据数量）

1. `application_id → expense_line_id → invoice_id/payment_id`：一张票含数项费用可拆行，一条费用可多张票；要求净合规支出不重复核销。
2. `event_id + contest_edition + stage_id → participant_roster → registration_fee`：同名不同届、同届不同赛段、同赛段不同队伍不得草率按名称去重。
3. `invoice_id → tax_state(R)`、`payment_id → paid_to/paid_by`：**票面事实与银行支付事实独立**；系统查验接口不可用时只报告无法查验。
4. `fund_id → allowed_category + budget_balance + authorized_project_lead`：经费负责人不等于申请人、实付人或受益学生。
5. `activity_id → activity_report + participation_count + prize_recipients`：存在未发放奖品和真实库存时需按场景解释数量差异。
6. `manuscript_id/article_title → journal/acceptance/first_page → APC_invoice`；“稿件录用”是版面费的费用事实，不是综测论文获奖事实。
7. `patent_application_no → fee_type/fee_period → official_status → budget`：专利申请费、授权维持费证据发生阶段不同。
8. `policy_version + expense_date + submitted_at → deadline`：2025票据到2026年一季度的过渡条件不能套到2027年度。

## 5. 可选 vs 条件必需的反例

- 没有奖品的普通学生活动，`M-16/M-17`关于**奖品**的条件不触发。
- 对公统一付款的竞赛报名费，`M-10`学生本人付款流水不触发。
- 论文正式发表尚未发生，但有有效录用通知和票据，不能同时强要`M-19`。
- 刚创建采购需求，发票与验收是**未来材料**，申请根本不应先送T01。
- 纯外部服务合同结算，无论金额大小，若要求履约验收须送T04，不能凭T01已看过发票替代合同审查。

## 6. 非结构化图文信息要求（供以后C/D会话使用的**研究事实**）
