## 1. 实验问题与变量

核心问题不是「Agent 会不会输出合法 JSON」，而是三次递进地检查：

1. **V1｜规则已明确时是否能理解和分组**：给出规则编号与结构化材料，是否能提取责任、判断状态、区分材料缺件/待核/有权部门待办。
2. **V2｜分散条款是否能保真转为概念模块**：去掉事先编号，混合正式制度、后发修订、非权威草稿、分阶段要求、同案多操作，是否会漏掉并存问题或串用授权。
3. **V3｜文字理解能否落到真实执行逻辑**：必须写 `rules.py` 并生成 `test_rules.py`；未见过的隐藏案例直接输入其代码，检验能否泛化，以及自测会否强化错误的字段假设。

控制原则：A/B 独立、仅看到各自 Agent 输入 ZIP；Gold 和评测程序应在不可读评测环境；工作目录由用户指定，完整输出和实际终端记录必须保留。A/B 是**不同合成业务和不同题集**，不是同一试卷；不能把两个人的成绩直接理解成可控的同题模型对照实验。

**关键实例**：
- `A17/t1`：A 将「两种可采身份材料均缺席；未使用的路径核验值为 null」报为 `NEEDS_CONFIRMATION`，Gold 为 `NEEDS_SUPPLEMENT`。这是**不存在可用证据**与**已有证据等待核验**的界限问题。
- `B17`：B 主状态 `READY_FOR_REVIEW` 正确，但 `ruleRefs` 只体现 `R06/R16`，未证明 `R04/R05` 两项相互独立的代理/机构授权已完成核验。**答对状态不等于责任充分解释**。
- 结构化字段、显式 `Rxx`、六种已列状态与多为单条件变化的案例，使 GPT-6 Low 可以快速给出高分。用户反馈两名 Agent 约 30 秒完成；该速度不能单独证明理解差或泄题。

**可得结论**：在明确、规范的合成材料下，基本状态判断与概念分组能力较好。**不可得结论**：完整真实 MD 无损转换、模块实际可执行或 D4 开发已具备业务正确率。

**证据**：`离线测试_A_完整隔离包.zip`、`离线测试_B_完整隔离包.zip`、`测试A&B.zip`、`qa_review/scoreA.json`、`qa_review/scoreB.json`。两个完整包内嵌 Agent 输入与评测包，故不得整体交给受测 Agent。

**其他可核实问题**：
- B 的 29 个 `otherIssues` 全空。部分并发风险出现在 `reason`，但例如 `B2-09` 馆方待办被遗漏；不满足「逐操作报告全部已知问题」。
- A 的部分 `sourceRefs` 罗列全部章节而非针对当前问题定位；来源覆盖不能只靠通篇引用。
- 可见的 A/B 归档输入未包含 Gold，所见会话记录未显示读 Gold；但这**不证明**运行环境物理不可访问。两名 Agent 的中间生成脚本在 `/tmp/make_answer.py`，B 还有 `/tmp/placeholder`，违反指定工作目录的文字约束（不等于泄露答案）。

**证据**：`离线盲测V2_[A|B]_Agent输入.zip`、`离线盲测V2_[A|B]_答案与评测.zip`、`测试A&B-V2.zip`、`V2_双Agent独立审查报告.md`、`离线盲测V2_实验实施说明.md`。

## 5. V3｜可执行规则、隐藏题与反例自测

**提交约定**：两名 Agent 都必须实现完整离线 Python 判定器，保存公开判断，编写不少于 10 个自主反例并保留运行记录；隐藏样本由评测者直接喂入受测 `rules.py`，不得只评价书面规则描述。

| 指标 | V3 A | V3 B |
|---|---:|---:|
| 公开状态 | 21/22（95.45%） | 14/21（66.67%） |
| 隐藏状态 | **36/38（94.74%）** | **18/53（33.96%）** |
| 公开 issue micro-F1 | 97.30% | 52.31% |
| 隐藏 issue micro-F1 | 95.24% | 35.00% |
| `answer.json` 与 `rules.py` 结果一致 | 是 | 是 |
| 责任/模块数量 | 11 / 7 | 11 / 5 |
| 原评分器机械分（/75） | **67.15** | **34.89** |
| 自测调用缺陷解释性校准后（/75） | **72.15** | **39.89** |
| 人工 25 分 | NOT-RUN | NOT-RUN |

**A：一个错误假设使三题出错**。`rules.py` 将数字接收链签发者写为 `platform`，而案例的合法值为 `centre`。公开 `A3-05/m1` 与隐藏 `A3-H10/m1`、`A3-H20/m1` 均产生错误的 `CHAIN_MISSING`。其自测使用了自己设想的 `platform`，同样错误却全绿。独立诊断仅修改隔离副本的这一个枚举值，得到公开 22/22、隐藏 38/38、状态和 issues 全匹配；**不能把修补后的诊断分数算为 Agent 原始交付成绩，也不能推广为真实系统零缺陷**。

**B：不同材料结构被错误强制同构**。通用 `match_scope()` 对每份材料一律要求 `recordId + operationId`；真实输入中身份材料主要有 `ownerId`，复制许可和代理委托使用 `operationIds[]`，只有部分纸质凭据才有单个 `operationId`。因此身份被错误判缺件：公开 19/21、隐藏 51/53 条额外出现 `IDENTITY_MISSING`；复制许可额外误报公开 7 处、隐藏 17 处；还有未到期义务的无谓 `deferred`，导致很多合法申请被错误拒止。B 的 13 项 `unittest` 依赖自己编造的单数字段，全部通过，但没有覆盖真实案例的合法基线。

**评测器问题（不能倒扣模型）**：
- A 使用一个 `check()` 调度实际 14 条成功测试，AST 静态扫描只看到 1 个断言，原自测项判 0；Agent 日志末行称 13 条，但真实输出是 14 条 PASS。
- B 使用有效的 `import rules` + `unittest`，原评分器以 `python -I test_rules.py` 运行时模块路径缺失导致 `ModuleNotFoundError`，错误判 0；在提交目录按正常运行方式 13 个测试均通过。
- 「+5」校准只纠正评分器对自测存在性的错误，**不是官方重评分**；Gold 未修改，人工语义 25 分尚未签署。
- 隐藏「错误 READY」专项未检测到重大越权放行，不等于安全通过；B 主要失误是**系统性误拒与虚假缺件**。

**可得结论**：V3 成功测出了「报告阐释得通、Python 能跑、Agent 自测全绿，真实输入仍可能大量出错」；下一步应转为真实 G01 模板制作与合成案卷运行，而不是无限继续增加同类离线题。

**证据**：`V3_[A|B]_Agent输入.zip`、`V3_[A|B]_隐藏答案与评测.zip`、`测试A&B-V3.zip`、`V3_双Agent独立复核与评测器诊断报告.md`、`V3_实施说明.md`、`v3_review/grade_[A|B].json`。

## 6. 跨三轮的确定性结论与不确定性

### 6.1 已被实验支持

1. **提示词不能代替真正的数据契约核验**。先从真实输入中验证字段、类型、枚举、数组/单值及对象适用范围，再编写或复用模块；V3 A/B 均违反了这一点。
2. **共享责任 ≠ 共享证据结构**。不同材料可以共同满足「限定对象/操作」的责任，但 `ownerId`、`operationIds[]` 等类型不能被强行变成同一字段。
3. **状态命中 ≠ 解释完整 ≠ 责任无损**。V1 的 `B17`、V2 的 `otherIssues` 和 V3 的实现失误显示三层可能分离；必须分别审核。
4. **错误拒止也是真问题**。不只对「错误 READY」设门槛；合法证据被当作缺失会造成大量无谓补件或重复人工审核。
5. **自测全绿不构成独立质量证明**。自建样本可能和错误实现具有相同的假设；需从**真实公开样本**建立至少一个正确合法输入，再做单字段微变形和独立隐藏测试。
6. **评测器必须被复核**。V2 原文/GOLD 可能不充分，V3 自测调用方式有不兼容；机械分要保留原值，并解释诊断修正，不偷换基准。

### 6.2 尚不能推断

- GPT-6 Low 或任何模型能全量、忠实地转换五份 G01 原始 MD。
- 自然语言模块、D1 作者态、D3 冻结版本、D2/Pi 是否在真实 G01 全场景可执行。
- 成都理工大学当前规章、审批主体、办理材料已经得到独立确认。
- 真实在线模型的业务准确率、正式部门批准或 D5 人机编辑体验。
- A/B 分数差就是可重复的模型能力差：题目和样本不同、运行时与脚本实现也不同，需同题多种子重复实验方可比较模型配置。

## 7. 转成 D4 提示词的最小有效约束

这不是一份新业务调查规范，避免把提示词增写成冗长研究程序。让各 Agent 依次证明：
1. **实际输入契约**：完整 MD 的 SHA；实际正例中每类材料的字段/值/类型/对象/operationId/生效版本；不能仅凭模型构造测试结构。
2. **原文责任 → 技术位置**：每条责任、分支、例外、阶段和人工权力必须进入 Check/受控 gate、manual-only、policy-awaiting 或明确 tooling-blocked；无去向是漏项。
3. **先做一份完整技术模板，再做真实动态实例**：不要把写出 77 个自然语言 Check 等同于完整业务功能。
4. **独立预期先于作者结果**：可使用不同 Agent 构造 Gold，但不能由制作 Agent 看自己的输出后修改 Gold。
5. **正反例成对且保留并发问题**：从真实样本复制，仅修改一个关键字段的反例；验证正确放行、错误放行、错误补件及未知的可观察差异。
6. **保存实测**：CLI 命令、退出码、配置隔离、D2 计划、SourceRef/Subject/RuleSpec、Pi 服务 Case/Run/回执、版本与 digest；未执行必须为 NOT-RUN。
7. **分别签署三层结论**：模板作者态有效、合成服务/规则行为通过、在线模型/本校制度/正式审批未获证明；不能将几层合并为一个 PASS。
