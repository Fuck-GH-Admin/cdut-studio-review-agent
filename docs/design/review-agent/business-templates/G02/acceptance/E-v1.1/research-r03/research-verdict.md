## 最重要的负面发现

`G02-R03-C-T03-01`：T03 的外协身份路径与目标资源准入路径存在**可重现的文字歧义**。BR-02 的“按受益身份分流”可被实现者误读为与 BR-03 互斥，BR-03 与 SC-06 却要求两者叠加。合成假人 Contractor-Q 经有权学校联系人担保，拟访问 R1，网络部门通道已同意，**R1 资源属主尚未授权**。如果只运行身份分支，存在推断可以实施的危险解释；若要求两个独立许可都满足，则必须 `PENDING_RESOURCE_OWNER`。准确证据与其他变量见 RC04。

- **已实测：** C 母版固定 SHA 相同；上述三个互相有关的原句在 C 原文确实存在；封闭 S 反例完整列出。
- **仅推断：** 将「分流」实现成互斥后会导致授权遗漏。未见此实现，不指控真实系统已发生越权。
- **可观测修正判据：** C 作者显式确认 BR-02（具体资源）与 BR-03（外协身份）是两个可叠加、必须各自满足的义务维度；任何缺一者均不能由本模板推出已批/已开通。工程方若确实实现相关路由，应在独立合成数据上演示两种分支同时运行，而不是靠作者说“支持叠加”。
- **归因：** C 文本层 `STATIC_AMBIGUITY / RISK_CANDIDATE`，而非现成 P1 真正误判；只有真实运行或明确矛盾无法解释时才能升级技术/业务缺陷并按正式 E 复验。

因此不制造原 C 不存在的缺陷。**验证了 C 某处写对，也不等于 Gold 或 Agent 运行正确。**
