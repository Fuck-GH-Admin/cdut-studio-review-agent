## 2. 实施方式与运行权限

1. 各自导出 `TemplateVersion` 兼容定义和 `r02Metadata`，模板 ID/正式名称/源路径/源 SHA-256 独立；每个规则 `R001...` 是有稳定 ID 的单独 criterion，保留原始要求、真实 `F###/M###` 绑定及 `SRC-###` 研究索引。
2. 字段按 `F` 建立，材料槽按 `M` 建立，禁止将来源研究 SRC 伪装成用户上传的案卷材料；对有歧义的原稿字段类型保守用 `text`，不臆造枚举、数值区间或时效。原始字段说明和材料用途保存在抽取提示/槽描述。
3. 不足材料可以进入事实初审：槽位 `minCount:0`、`requiredAt:'decision'`，规则自行标注需补证/不可读/来源失联；这一选择不等于任何事实已经核验，更不等于豁免最终所需材料。
4. 无可证伪的结构化计算操作时，规则只设 `semantic` 或 `manual`；涉及政策、权限、奖金、正式决定/撤销和复核的检查优先 `manual`。所有模板 `status:'draft'`、`officialSchoolTemplate:false`、`policyEvidenceStatus:'UNCONFIRMED'`、`policyVersionIds:[]`、`policyRefs:[]`、`autoPassPolicy.enabled:false`；没有 `approval` 输出或学校远端回写。
5. 工作流仅给出本地系统核对→reviewer 人工复核→teacher 人工复核的**通用本地研究建议流程**。这两个角色不表示学校正式批准权限；如需最终机构/签字/批准金额，必须获得当期权责证明，沿现有 V3 Main 可信身份及 CAS/Plan/Run 门禁办理。

**重要集成界限（跨批次 P1 依赖）**：当前 base 尚不存在本领域共享 `r02-template-catalog/index.ts` 或对应 compiler 统一接线；本批按独占文件规则不创建共享注册器、不更改 Plan/Run bridge。现有 TS 定义可被该统一路径导入，每个 criterion 有精确标识和元数据绑定，**但不能声称这五份模板现在已在客户端目录中显示、可创建案卷或已真实运行 V3 Plan**。集成 Owner 必须在共享注册/编译与端到端测试后关闭这一项。`researchBindings` 不可被无视后声称材料覆盖或计划检查完成。

## 4. 具体问题与处置

明细及可复核位置见 `S06-B.tsv`，按模板列出三类 P2：

- **POLICY-CURRENTITY**：全部五项都有校方当期具体业务规则、批次、权责或废止/修订状态待确认；在代码中全部转人工，未编造 PolicyVersion。
- **CROSS-TEMPLATE-DEDUPE**：赛事、科研成果、课程实践、入驻资格和创业资助的跨模板重复使用尚须真实的案卷事实账与有权政策确认。本批保留各项去重边界与 R 级规则；不自动跨模板加分、重复发奖、拨款或合并事实。
- **FIELD-TYPING**：研究稿存在类型与可信主数据描述，但缺少足以安全确定当期系统枚举、授权接口和约束配置的全套依据。保守使用可读文本与人工语义核对，不伪造自动数据规则。集成测试需补充受控字段抽取的真实证据。

未发现可以仅凭这些研究稿安全推定的学校生效日期、当期阈值、最终权限、奖励金额或政策例外；故不进行高风险正文重写。五份 canonical Markdown 与取回原件逐字节一致，代码在不改原稿的前提下设置人工门禁。补充校方证据时再按版本修订源文并更新 SHA-256/criteria。
