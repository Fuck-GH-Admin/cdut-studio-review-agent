## 实施方式与保护边界

- 每份原件的 F/M/R/SRC 四账均转为 V3 `TemplateVersion` 的 fields、materialSlots、sections.criteria 和 `r02Metadata`，所有 R001…Rn 均有稳定 criterion ID；metadata 另记每项 SRC/F/M 借位，供集成 Owner 编译 CanonicalPlan 使用。
- `sourceDocumentPath/Bytes/Sha256` 对应原件追加 LF 后的统一清单口径；`reviewedDocumentSha256` 则表示完整审阅稿的真实字节哈希。研究 SRC 不写入案卷 SourceRef。
- 当前 F 默认 text、required=false，M 默认 minCount=0：各模板的条件、学段和办理阶段不同，不把后置校方意见与未知校规转成提交时全局硬缺件；详细约束留在原始字段/材料提示与对应 R 审查要求中。
- 流程为本地建案定位 → 事实/语义审查与人工复核 → 有权人员确认；T01-T05 增加 `sensitive-access-gate` 人工阶段。全部 `status=draft`、`policyVersionIds=[]`、`autoPassPolicy.enabled=false`、无 approval 输出、无 deterministic 假规则、没有学校身份/远端写回。
- 未触碰共享注册器、Plan/Run bridge、Main/IPC/Pi/Renderer；这些文件的接线、稳定 checkKey 与实机 E2E 是集成 Owner 工作，不能因为独立模块存在就声称 V3 已运行。
