## 实际缺口和处理

详见 `S01-C.tsv`。三个 P2 均是可继续实现但必须向使用者披露的证据/集成风险；它们不会隐性升级为 P0/P1，因为模板保持未确认并强制人工处理。

1. **S01-C-001（P2，政策当期性）**：2026 校级教通字〔2026〕3 号完整正文与不同学院接收指标/评分细则未取得。§04 SRC-003/004/005/013/015 只能支持其明确的存在、时间和局部阶段，不能推出所有学院招生名额、截止日、权重或资格硬门槛。运行时所有依赖 F022/M021 的 R 保留 `POLICY_UNCONFIRMED` 语义与人工门禁。
2. **S01-C-002（P2，研究生和特殊身份）**：§02/§03 C06/C08、SRC-004/009，合作项目附件与研究生当期正式专业变更权限/适用范围没有闭合。只保留条件化检查和人工导流，不套用本科程序。
3. **S01-C-003（P2，共享运行接线）**：基线 `r02-template-catalog/index.ts` 尚未登记本模板，V3 draft 候选与真正的 Plan/Run 编译还须集成 Owner 完成；本批不可越权修改共享文件。专项测试验证定义、规则来源和安全门禁，**不能据此声称模板已在应用内上线或完成真实案卷端到端运行**。

## 剩余风险与交接

- 需要有权校方确认 2026 通知全文、生效关系、专业指标/录取权重与特殊招生限制；不得以历史 2019 或 2024 文件代替现行规定。
- 研究生及合作办学审批链缺少权威完整附件；不推定校内签批人、时限和项目例外。
- 官方学籍、成绩、专业名单、签章和学校决定接口未由本批接通；用户上传文件只提供可核线索。
- G01 只处理姓名/身份证等字段纠错；真正主修专业变更仍经 S01-T04 权威决定链，跨校转学交 S01-T05。
- 全流程可用性须由集成 Owner 接入共享注册器并使用合成案卷跑 V3 Plan/Run；本 PR 只保证批次文件所有权内的可审查候选定义。
