## 3. 业务和权限分层

| 业务段 | 事实/技术审查 | 不得替代的学校权力 |
| --- | --- | --- |
| P1 申请受理 | 申请主体、联系与目标信息、身份核验回执、登记时间；M001/M002 当前材料与 M004 后置回执分开 | 正式受理、代理权限认定及补正截止由有权办公室确定 |
| P2 定位/存在性 | 持有部门检索、正式公开 URL、版本、是否属档案/其他业务 | 不因 404 或模型未找到就判“信息不存在”或不予公开 |
| P3 范围/保密/第三方 | 安全元数据、第三方权益、受众匹配、删节版本与 hash，一项 R 一个检查 | 法定定密/解密、保密意见、公共利益例外和第三方权益权衡由有权主体审查 |
| P4 答复审批 | 核对已签答复及可信授权证明的存在、范围、版本 | 不生成学校正式“公开/不公开/部分公开”签批；不伪造岗位或 PolicyVersion |
| P5 实际披露 | 独立核对批准版 hash、具体收件人、渠道、送达日志 | 本模板无发邮件、放链接、写回 OA/公网发布、直接发送附件的执行动作 |
| P6/P7 撤回/监督/归档 | 保存实际已披露事实、错版本重审、投诉与复核待办 | 不“撤销”已发生的披露，不擅定救济期限或最终复核结果 |

R001/R003/R006/R009 只允许安全脱敏元数据的语义**提示**；其余 25 条按 `manual`。R010–R022 中的保密、个人/商业秘密、第三方、公共利益、授权、正式答复和送达均无确定性自动通过。`M002`（身份回执）及 `M007/M008`（保密/裁断）等关键敏感材料槽限定安全 `text` 引用和人工提示，不允许借此收集全证件影像、D4 原件或外网 OCR。**材料槽的描述并不是主进程强制 D4 隔离**；共享摄取层仍须在上线前做拒止验证。

全部 F 字段及 M 材料槽使用可延期/可条件处理的配置（`required:false`、`minCount:0`）；缺材料由对应 R 按阶段产生 `NEEDS_MATERIAL` 或校方内部待办，不能在 P1 因为未有 M008/M014/M015/M022 等后置学校记录就拒绝申请。所有结果都属案内事实、差异、风险和补件清单。
