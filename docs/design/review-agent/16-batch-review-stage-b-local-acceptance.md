# 批量审核 B 阶段：本地验收说明

> 对照 [16 批量审核自动化规范](16-batch-review-automation-and-issue-clustering-spec.md)；本文件随功能分支提交，不表示 C 阶段已实现。  
> 验收代码分支：`feat/batch-review-triage-v1`，PR #1 保持 Draft，**不自动合并**。

## 本次必须完成的闭环

1. **共享有效性门槛**：同一运行被分流为技术异常时，不可能同时作为当前有效问题组出现。对 manifest 模板版本、外层版本、政策锁、输入哈希、检查覆盖和读取情况使用一致校验。既往已进入正式决定/正在补件的案卷不当作新的待处置问题组。
2. **批次执行与恢复**：队列只消费显式 `queued`；一个案卷失败不影响后续；当前进程重复启动拒绝；崩溃遗留 `running` 由人工显式恢复为待核查失败，不自动不明状态重跑。
3. **定向重试**：仅对选择的 `failed/paused` 或审核运行内容不完整的 `done` 技术异常案卷重新入队；正常完成或已形成正式业务决定的案卷不得悄悄重跑。
4. **同类问题人工集中处理**：保守按规则、状态、原因聚合；可选择某组及部分案卷；输入依据与补正要素；服务器重新读取当前案卷、运行、证据、模板、业务阶段，返回逐案可处理和排除理由。
5. **正式写入**：预览后必须明确勾选确认；采用稳定操作 ID，将适用案卷**分别**交给原 V2 单案处置/补件/业务决定事务；记录人工来源、输入哈希、审计回执；返回逐案已处理、排除、冲突或失败数。不支持无来源证据、不符合模板授权角色、其他角色待办、过期输入或未完成业务门槛的批量审批。
6. **幂等与中断可查**：同操作 ID 同载荷重复调用返回已保存结果；载荷漂移拒绝；批量操作结果逐案原子落盘，进程中断不可假报全部成功，也不会未经核查自动重发正式决定。
7. **问题组操作结果可见**：刷新数据后仍保留本次提交回执与排除/失败原因，用户可进一步打开案卷核对。

## 本地测试步骤

```bash
git fetch origin
git switch feat/batch-review-triage-v1
git pull --ff-only
bun install --frozen-lockfile
bun test --isolate --timeout 30000 \
  packages/shared/src/review/batch-review-triage.test.ts \
  apps/electron/src/main/lib/review/batch-store.test.ts \
  apps/electron/src/main/lib/review/batch-group-action-service.test.ts
bun run typecheck
```

**UI 场景**：

1. 创建使用同一已发布模板版本的多案批次并执行审核。确认“检查已完成”不被混淆为正式通过。
2. 用两个具有可定位证据的同类异常案卷进入问题组，点击“人工集中处理”，取消选择其中一案后预览、输入真实核实理由、勾选确认并提交。只有选定且服务器验证通过的案卷产生单案 V2 事务记录，弹窗展示逐案回执。
3. 再次打开案卷，确认对应 `dispositions`、`supplements` 或 `decisions` 和 `receiptLog` 追加了人工来源记录；相同操作不能凭再次点击无声重复创建正式决定。
4. 测试没有可追溯引用、模板版本不一致、材料变更、教师/评委阶段、待补件、需要人工认定及旧预览。它们应被排除/阻断，而不是借批量操作通过。
5. 使用中断批次“恢复中断”操作，恢复后的案卷需要人工查看运行历史再定向重试；正常已完成的案卷不重跑。
6. 对审核结果检查缺失但队列已标为 `done` 的技术异常进行单案重试；正常有效 `done` 不允许此操作。

## 不包含的 C 阶段内容

- 无人值守的自动通过/自动退回及批次自动审批策略开关；
- 补件回应后自动识别受影响检查并继续完整审核、自动最终定稿；
- 学校审批授权接入与远端正式生效；本阶段操作者标记为**本地 reviewer**，不冒充校方认证身份；
- 大规模跨案关系检查、基于大模型的模糊聚类及跨案一键决定。
