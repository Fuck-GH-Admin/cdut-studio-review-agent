## 2. 六份本地参考逐项使用

所有资料已在 `../../../../references/`。本次没有安装或运行它们的服务，也没有访问示例账号。版本和下载校验见 [参考清单](../../../../references/README.md)。

### R01：cqes4cs，综测结构、人工修分与异议

本地 `cqes4cs-v1.1`，v1.1 / `c122f93`。检查 `cqes4cs.sql`、`MaterialController.java`、学生/成绩模板。SQL 中 `authentication_score` 记录建议分数与异议理由/结果；`authentications` 记录审核人、时间和通过方式。控制器有教师修分、拒绝说明、学生撤回和异议处理入口。[项目来源](https://github.com/quarkape/cqes4cs)

**转为需求**：事项级分数和案卷汇总分开；原申报、AI 建议、教师最终值分别留存；异议必须关联原决定和规则版本；等级分值、指标权重以可配置数据表达。测试用其表结构和列关系，重新生成虚构学生。异校政策只能用于解析测试。前后端 MIT，实际移植须保留许可。

### R02：ComprehensivePerformanceSimplifier，证明分选与已使用状态

本地 `50862b8`。检查 README 与 `mian_UniTestApp.py` 的图片组、分选、已使用、错误结果及确认加分处理。它解决的实际痛点是“一组图如何分成多个申请事项”，并保留人为确认分数。[项目来源](https://github.com/SXU-Opensource-Association/ComprehensivePerformanceSimplifier)

**转为需求**：证据与事项为多对多关系；同一图可以支持不同事实，是否允许重复计分取决于规则；需要待绑定区、拆分/合并、已使用提示、错误标记和补证动作。输入依赖特定腾讯文档导出，仓库没有完整标准测试包，我们需自己制作适配器与样本。Apache-2.0。

### R03：evaluate，综测维度与表单通用性的提醒

本地 `e6116b6`，仓库只有 README。描述了课程/GPA、德育、体育、加分、证明审核、班级和辅导员，但**没有可验证的系统源码或数据库**。[项目来源](https://github.com/mikenote/evaluate)

**转为需求**：完整综测需要基础成绩和加分分开，权重和适用维度由模板设定；不能把某个示例权重作为 CDUT 规则；其价值用于场景覆盖检查，不能称已验证实现，也不能拿它生成准确率真值。未见公开许可。

### R04：scholarship-system，配置字段、分阶段审批与补件

本地 `3b659f2`。核查 `backend/app/models/application_field.py`、`enums.py`、`review.py`、`document_request.py`、`college_review.py` 与 `mock-student-api/README.md`：动态字段/材料配置；申请结果和流程阶段分开；子项分别审核形成部分通过；补件有原因、期限、履行/取消状态；排序与定稿；模拟学籍 API。[项目来源](https://github.com/jotpalch/scholarship-system)

**转为需求**：模板定义表单与材料槽，流程实例独立持久化；按事项做决定；补件是可跟踪任务；排序定稿后冻结版本；当前无校方 API 时使用标准适配器的模拟实现。不能直接搬其 FastAPI/数据库/MinIO 系统替换 Electron。README 声明无公开许可，本设计只借鉴概念，不复制源码。

### R05：RDA TIGER，评委审核不能只找“错误”

已下载全部 9 文件。核查三份评委 PDF（OC/CG/TG）及三份 XLSX 的列/公式，并渲染 OC 首页确认布局。表单先声明利益冲突，区分资格、1–5 分量表和可对外反馈；部分维度只评分申请者选择的领域，不把未选项当零分。`Open Calls…xlsx` 的 `August 25!A1:Y1` 是提交记录，`Results!B2` 等按申请 ID 汇总评委均分；`Overview…xlsx` 包含申请元数据、评委、分项与总分展示。[数据来源与许可 CC BY 4.0](https://zenodo.org/records/17734784)

**转为需求**：资格审核和质量评分两种输出；支持不适用项、利益冲突回避、独立评分、分歧提示、反馈可见范围。这些数据可测解析、评分导入和公式；评分本身是人的判断，不能当 AI 的唯一正确分数。不要声称该数据有完整“申请原件—证据—官方终审”标注链。

### R06：OULAD，关联数据与大批量输入

保留 UCI 托管 ZIP，实际检查 7 张 CSV 表头：学生、课程、考试、成绩、注册、VLE 活动及交互。可通过学号、课程和考试 ID 关联，包含缺失值。[UCI 数据来源](https://archive.ics.uci.edu/dataset/349/open+university+learning+analytics+dataset)

**转为需求**：稳定外部 ID、成绩关联、缺失值处理、批量队列和规模测试。没有证书、综测加分规则或审核决定；不能用其人口特征推定资格，也不能拿学习结果当材料审核标签。CC BY 4.0；示范包只分发必要小样本及署名。

## 5. 差距转成设计决策

1. 从 `DomainPack` 升级到“模板版本 + 规则版本 + 流程实例”；保留 DomainPack 作为默认词汇和展示标签。
2. 从“模型一次返回问题列表”升级到“检查矩阵 + 证据链 + 已验证发现”。没有问题是合法终态，未检查必须显式保留。
3. 把 AI 理解、确定计算、人类决定分成不同结果对象，统一呈现和交接。
4. 以现有文件/IPC/状态体系承载流程，用共享 Pi 工具与模型出口执行；补审核专用步骤恢复，不假设通用 Agent 已完成该能力。
5. 本地即可操作全流程并往返材料包；校方接口通过端口替换，真实多人身份/权限由共享服务实施。全部纳入最终验收。

## 6. 补强计划合并与严重性校准

原业务完善计划的 7 个 P1、4 个 P2 及 5 项补充差距全部保留，统一编号 H01–H16。原始审查中的编号保留用于复现；下表把同一条目中的正确性、体验和待建能力拆开，避免把全部子问题都定为同一严重性。优先级表示对可靠使用的影响，不表示开发工时，也不删减最终功能。

- **P1**：会形成错误或不可信的当前结论、分值、出处、案卷或报告，必须先修。当前没有证据将其定为 P0 安全事故。
- **P2**：不直接改变判断，但妨碍理解、复核、恢复或交接；完整产品必须通过相应验收。闭环缺失不能因标 P2 就长期搁置。
- **目标能力缺失**：模板、业务角色、审批、OCR、批次、评委等是通用产品必需能力，按 M1–M5 依赖交付。若缺失能力导致系统虚称已经审核、已经授权或已经批准，相关错误语义按 P1 处理。

| --- | --- | --- |
