## 1. 结论摘要

- **演示场景可撑住**：演示案卷（张三 fixture）全流程——三栏浏览 → AI/确定性双路径审核 → 问题卡三栏联动 → 助手追问 → 报告导出——已实测通过，且该路径天然避开全部 P1（锚点精确、单一依据单一申报、证明齐全）。前提：配置一个启用的模型渠道；无渠道时确定性引擎可兜底。
- **真实使用未达标**：用户自建案卷路径存在 7 个 P1 正确性问题（漏审/串案/误报/伪出处）与 4 个 P2 闭环缺失，另有角色体系等设计明确项未实现。
- 实施原则：先正确性（P1），再闭环（P2），最后扩展（角色/领域/格式）；用户构思合入后统一排批次。

## 3. P1 正确性问题（真用前必须修）

> 每条：问题 → 修复思路 → 涉及位置 → 验收方式。证据细节见审查报告对应编号。

### P1#1 证明清单与审核未接通（漏审证明）
- 问题：导入证明只追加 SourceDocument，不生成 EvidenceDocument；文本证明原文不进审核请求；PNG 走 Vision 但缺文件/块 ID 标记且第 9 张静默丢弃；扫描 PDF 不转图。
- 修复思路：导入时同步产出证明事实（复用识别通道或延后到识别步）；审核请求为文本证明附带真实 `documentId/blockId` 标记；图片加文件名+序号标记并落实"数量上限→显式未审核清单"；未识别/超限/被剔除的文件进右栏可见清单（对齐设计 §4.4「解析失败不从分母消失」）。
- 位置：`case-import.ts:101`、`ai-review-service.ts:574/141`、`CenterPanel.tsx:194`。
- 验收：导入 txt 证明 + 3 张图 → 案卷证明卡 >0、其特有文本出现在审核请求、超限图片出现在未审核清单。

### P1#2 多份依据只审第一份
- 修复思路：大纲生成与审核消费全部启用的规则文档（合并或分文档多轮）；LeftPanel 列出全部依据及启用状态；冲突/版本交给用户确认（对齐设计 §4.3）。
- 位置：`LeftPanel.tsx:38`、`use-review-actions.ts:313`、`ai-review-service.ts:568`。
- 验收：两份依据各有特有文本出现在审核请求；第二份的专属限制能产出问题卡。

### P1#3 真实案卷生成失败混入演示校规
- 修复思路：fallbackOutline 仅限 `DEMO_CASE_ID` 案卷；真实案卷失败→显示失败原因 + 人工补充入口，不回填演示锚点。
- 位置：`ai-review-service.ts:240/284/325`。
- 验收：自建案卷无模型时不再出现 7 条演示规则。

### P1#4 空结果/失败/未覆盖三种状态混淆
- 修复思路：合法空数组不再降级 mock；RightPanel 按 `run.status` 区分渲染（failed 显示失败态）；覆盖摘要改为审核结果显式给出逐事项状态（covered/compliant/conflict/补件/未覆盖），不再从"有无问题卡"反推；模型返回 itemId 校验属于本案。
- 位置：`ai-review-service.ts:498/634/660`、`RightPanel.tsx:100`。
- 验收：AI 空数组→"未发现问题"；failed run→失败态而非"未发现问题"。

### P1#5 等待审核时切换案卷会串案
- 修复思路：异步回写前校验 `run.caseId === 当前案卷`；任务按 caseId 隔离存取；切案卷不清 running 标记或禁止并发发起；同案卷并行任务按最新 nonce 合并。
- 位置：`use-review-actions.ts:322/342/363`、CaseManagerBar。
- 验收：审核 A→切 B→A 返回不污染 B；识别返回不把页面切回 A。

### P1#6 修改材料/领域后旧结果未失效
- 修复思路：写操作（导入/重识别/大纲回写/领域切换）递增案卷 `inputVersion`；渲染与导出时比对 run.inputVersion，不一致标"结果已过期，请重审"；报告绑定输入版本快照。
- 位置：`use-review-actions.ts:281/229`、`report-service.ts:73`。
- 验收：换领域包后右栏显示过期标记；导出拒绝或注明过期。

### P1#7 出处不可核验（伪锚点）+ 联动偏差
- 修复思路：两步走——①给模型完整真实来源标记（真实 documentId + 块 ID 清单 + 图片文件映射）；②返回锚点做存在性核验，非法锚点降级为"仅定位到此文件/待确认"并标注原因；依据侧高亮固定蓝色（`SourceBlockView.tsx:98` 的 severity 着色改规则侧强制 blue）；文件级锚点只导航到明确容器。
- 位置：`ai-review-service.ts:509`、`SourceBlockView.tsx:98/190`、`document-service.ts:47`。
- 验收：伪造 blockId 的结论不再以红卡原样展示；点红卡中栏有明确落点；左栏规则高亮恒为蓝。

## 4. P2 处理闭环

- **P2#8 人工纠正路径**：字段/大纲可编辑、事项-证明绑定确认、文件替换/停用、问题处理状态（确认/误报/补件/忽略）+ 复核备注。需扩展 shared 类型与 IPC（现有 manual/confirmed/ignored 类型字段已预留），`report-service.ts:89` 的 manualNotes 接真实数据。

- **P2#10 报告充实**：真实审核类型、事项名称映射、detail/suggestionText、原文引用与文件位置、覆盖与输入版本、人工记录；导出成功反馈（顶栏按钮目前无反馈）。
- **P2#11 助手上下文**：纳入选中事项对应的申报/证明原文片段与经核验规则；大案卷按选中事项裁剪；引用可点击回看。

## 5. 设计已明确、审查未列的差距

1. **角色体系**（设计 §2）：学生自查/老师复核同页不同权限；"学生不能把 AI 建议标成老师批准"。当前无任何用户角色概念——需要与用户构思对齐后再定（涉及案卷元数据、按钮可见性、决定记录署名）。
2. **建议分数**（设计 §4.3）：AI 路径直接采信 suggestedScore，无"规则分值明确才输出建议分及计算依据，否则待确认"的守门。
3. **领域包填充**：活动审批无独立规则包；自定义包无类别/检查项编辑 UI；合同/报销问题类型在卡片中文标签表缺映射（badge 可能为空）。
4. **格式与入口**：扫描 PDF 无 OCR；RTF/ODT 在过滤器可选但 `DOCUMENT_EXTENSIONS` 不含（导入必败）；ZIP 材料包无解包；一次只能选一个文件。
5. **模型出口显示**：网关取第一个启用渠道，本区不显示/不可选具体模型；顶栏状态仅挂载时读取一次。
