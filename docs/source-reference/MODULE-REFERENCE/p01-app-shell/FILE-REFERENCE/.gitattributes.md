# .gitattributes

## 1. 结论与边界
Git 属性配置（纯配置，无运行时）：为 `apps/electron/default-skills/**/SKILL.md` 固定 LF 行尾（`.gitattributes:2`），动机是默认 Skill 的 frontmatter 需跨 Windows/macOS/Linux 一致解析（`.gitattributes:1` 注释自述）。边界：只做行尾/text 规范化，不含 diff 策略、二进制标记、压缩或合并策略；不被任何运行时代码读取。

## 2. 导出与关键符号
不适用，依据：纯 Git 属性文件，无 export/符号。键清单（规则仅 1 条）：`.gitattributes:2` `apps/electron/default-skills/**/SKILL.md text eol=lf`——`text` 声明文本文件、`eol=lf` 固定工作区 LF。

## 3. 内部逻辑与关键流程
不适用，依据：无执行逻辑。工具行为（推断自 git 语义）：git 在 checkout 时按 `.gitattributes:2` 对匹配路径产出 LF，commit 时按 text 规范化入库；规则行之外无流程。

## 4. 调用者与调用链
入向：git 工具链（checkout/add/commit）自动读取，属工具约定；冻结树内无代码读取本文件（全树字符串检索 `gitattributes` 仅命中本文件及 work/ 报告文档，无 .ts/.js 读取点）。出向：无。目标 glob `apps/electron/default-skills/` 在冻结树真实存在（含 automation、brainstorming、docx、executing-plans、find-skills 等子目录）。

## 5. 数据 I/O、读写与副作用
不适用，依据：本文件无 I/O 代码。副作用主体是 git：匹配文件工作区字节为 LF（副作用说明限定于工具层，非本文件逻辑）。

## 6. 分支、失败、取消与恢复
不适用，依据：无分支、无错误路径；glob 不匹配时该规则无行为。未匹配路径的 autocrlf 兜底取决于本地 git 配置（未知，未在本树验证）。

## 7. 权限与权威状态
无权限分支，依据：本文件无 sender/role 检查。权威方为仓库提交者（变更走代码评审流程，属仓库治理，非代码逻辑）。

## 8. 修改影响面
删除或改写 `.gitattributes:2` 会导致 Windows 检出的 SKILL.md 含 CRLF，frontmatter 解析随平台漂移（`.gitattributes:1` 注释自述的失效模式）。影响面限于 `apps/electron/default-skills/**/SKILL.md` 的行尾字节；无代码依赖，无测试同步需求。
