# API-REFERENCE：实际接口、调用条件与错误规则

基线 `05fb2565e20eb1760233696be1832f68196b37c2`。前置 [CODEBASE-MAP 独立 PASS](../GATES/CODEBASE-MAP.json) 后编写。本文的“已接线/实现”均为**冻结源码静态核对**；Electron、模型、网络、学校系统与真实文件选择器 **NOT_RUN**。完整入口见 [CODEBASE-MAP](CODEBASE-MAP.md)，全部符号、IPC 位置、桥接签名和工具 schema 见 [API-REGISTRY](API-REGISTRY.md)。源码类型是字段及联合类型的权威；现有单文件手册的接受状态由逐文件索引明确标注，不以本页替代。

## 1. 接口边界与共同约定

| 边界 | 实际调用方式与权威 | 调用限制/错误 |
| --- | --- | --- |
| Renderer → Electron | `window.electronAPI` 的声明 [apps/electron/src/preload/index.ts:272](<../../baseline/source/apps/electron/src/preload/index.ts>)；实现对象经 `contextBridge` 暴露 [apps/electron/src/preload/index.ts:4705](<../../baseline/source/apps/electron/src/preload/index.ts>) | 暴露点没有 `process.isMainFrame` 条件；不能据此推断任意调用已经得到业务授权。 |

| Main → Agent | `agent-service.runAgent` [apps/electron/src/main/lib/agent-service.ts:277](<../../baseline/source/apps/electron/src/main/lib/agent-service.ts>) → `AgentOrchestrator` → `PiAgentAdapter` [apps/electron/src/main/lib/agent-service.ts:54](<../../baseline/source/apps/electron/src/main/lib/agent-service.ts>) | 运行实例拥有会话执行权；重复 active run 会拒绝，不能把请求到达当作已受理。 |

IPC `invoke` 返回 Promise：handler 的 throw 导致 reject；有些业务服务返回 `ReviewCommandResult` 联合而不 throw，有些读取以 `undefined`/`null` 表示不存在，有些选择器以 `null` 表示取消。调用方应按**具体方法**区分，不能统一把 falsy 当失败或把 resolved Promise 当业务成功。事件订阅接口返回移除 listener 的函数，例如 `onImportProgress` [apps/electron/src/preload/index.ts:4762](<../../baseline/source/apps/electron/src/preload/index.ts>)，组件卸载应调用它。

`submitCommand(caseId, command, handler, source?)` 的 command 必须含 `requestId:string, actor:Actor, expectedRevision:number, type:string, payload:T`；`handler` 仅返回 `{summary,mutate}`，不自行加 revision 或写盘（[apps/electron/src/main/lib/review/case-store-v2.ts:191](<../../baseline/source/apps/electron/src/main/lib/review/case-store-v2.ts>)）。`source` 可带 assignmentId/sessionId 追溯。处理顺序是读取有效聚合 → 同 requestId+同 type/hash 返回旧回执 → 不同载荷碰撞拒绝 → CAS → archived 除 RestoreReviewCaseV3 外拒绝 → 校验/clone/mutate → revision 恰加1 → Receipt 与聚合一起写。幂等重试返回的 aggregate 是**当前读到的聚合**，不是旧 revision 快照；不可把重试结果当作当年 entity 的重建。磁盘写异常仍可抛出，调用者须重读回执确认是否已提交，尤其 rename 后目录 fsync 失败（[apps/electron/src/main/lib/review/review-v3-case-disk-tx.ts:114](<../../baseline/source/apps/electron/src/main/lib/review/review-v3-case-disk-tx.ts>)）。

原生聚合读取 `readAggregate(caseId)` 可从上一有效副本恢复**读取**，不会自动覆盖主文件（[apps/electron/src/main/lib/review/case-store-v2.ts:49](<../../baseline/source/apps/electron/src/main/lib/review/case-store-v2.ts>)）。`listCaseStorageIssuesV3()` 只诊断。磁盘锁不会按超时时间偷取；`recoverC2AbandonedCaseDiskLock` 是 Main 内部离线恢复接口，**没有 IPC 暴露**（[apps/electron/src/main/lib/review/review-v3-case-disk-tx.ts:170](<../../baseline/source/apps/electron/src/main/lib/review/review-v3-case-disk-tx.ts>)）。legacy `case-store.updateCase` 只在调用者提供 expectedRevision 时做 CAS（[apps/electron/src/main/lib/review/case-store.ts:278](<../../baseline/source/apps/electron/src/main/lib/review/case-store.ts>)），不能套用原生事务保证。

## 3. 普通 Agent 运行服务

`runAgent(input:AgentSendInput, webContents, onDraftPromoted?, onRunOwned?):Promise<void>` 的必填 input 为 `sessionId:string, userMessage:string, channelId:string`。`modelId/workspaceId/agentRuntime/additionalDirectories/triggeredBy/uuid/startedAt` 等可选项，以及 Main 专用 outcome、Goal、runtime session 回调，以 [packages/shared/src/types/agent.ts:1404](<../../baseline/source/packages/shared/src/types/agent.ts>) 为准。当前 `AgentRuntime='pi'`、默认 Pi，旧/缺失值通过 normalize 回落 Pi（[packages/shared/src/types/agent-provider.ts:12](<../../baseline/source/packages/shared/src/types/agent-provider.ts>)、[packages/shared/src/types/agent-provider.ts:33](<../../baseline/source/packages/shared/src/types/agent-provider.ts>)、[packages/shared/src/types/agent-provider.ts:41](<../../baseline/source/packages/shared/src/types/agent-provider.ts>)）；`AgentSendInput` 中“历史回退 Claude”的注释不代表当前行为。

- `onRunOwned` 是 Main 已取得执行权的观察信号，不能作为第二个运行器。busy 请求在 [apps/electron/src/main/lib/agent-service.ts:366](<../../baseline/source/apps/electron/src/main/lib/agent-service.ts>) 直接 reject；其他运行错误主要经事件总线和流式 error/complete 通知。调用方不能仅依赖 await resolve 判断“模型已正常完成”。
- `stopAgent(sessionId):void` 请求停止；`stopAgentAndWait(sessionId):Promise<void>` 等待真实 owner 生命周期释放（[apps/electron/src/main/lib/agent-service.ts:566](<../../baseline/source/apps/electron/src/main/lib/agent-service.ts>)、[apps/electron/src/main/lib/agent-service.ts:587](<../../baseline/source/apps/electron/src/main/lib/agent-service.ts>)）。Orchestrator 等待超时会 reject，不表示旧 owner 已释放（[apps/electron/src/main/lib/agent-orchestrator.ts:3672](<../../baseline/source/apps/electron/src/main/lib/agent-orchestrator.ts>)）。删除会话等后续操作应等待该 Promise 成功。
- `runAgentHeadless(input,callbacks)` 供外部桥接复用同一执行器（[apps/electron/src/main/lib/agent-service.ts:404](<../../baseline/source/apps/electron/src/main/lib/agent-service.ts>)）；审核运行专属会话的隔离与普通目录/事件投影限制仍由 Main 执行，不因 headless 变成普通聊天。

普通 Pi 的 buildRun 在 [apps/electron/src/main/lib/review/pi-case-review-service.ts:274](<../../baseline/source/apps/electron/src/main/lib/review/pi-case-review-service.ts>) 固定 input hash/effectiveRuleSetHash，但未写 inputManifest.planFingerprint；[apps/electron/src/main/lib/review/review-runtime-contract.ts:66](<../../baseline/source/apps/electron/src/main/lib/review/review-runtime-contract.ts>) 的 freezeAttemptIdentity 缺该指纹会返回 undefined。因此不能因共用类型或 manifest 就断言普通 Pi 与 T04 具有同一完整冻结 attempt。当前业务 Run 选择另排除 run-tpl/run-diag；最新业务 attempt 失败/进行中/取消时不会回退较旧成功 Run（同文件 :32 起）。

## 5. 直接 Pi 审核：模型实际可调用的四项工具

安装链是 `pi-builtin-tools` 根据 review-operator/用户轮/当前绑定构建三项工具（[apps/electron/src/main/lib/adapters/pi-builtin-tools.ts:2087](<../../baseline/source/apps/electron/src/main/lib/adapters/pi-builtin-tools.ts>)），Orchestrator 再执行 `selectDirectReviewStrictTools`（[apps/electron/src/main/lib/agent-orchestrator.ts:1706](<../../baseline/source/apps/electron/src/main/lib/agent-orchestrator.ts>)）。严格集合为以下四项，运行 profile 另加 `CompactContext`；通用 shell、文件工具、任意 MCP 与普通聊天工具被剔除，权限门在每次调用重核当前 binding（[apps/electron/src/main/lib/review/review-strict-pi-tools.ts:44](<../../baseline/source/apps/electron/src/main/lib/review/review-strict-pi-tools.ts>)、[apps/electron/src/main/lib/agent-orchestrator.ts:1852](<../../baseline/source/apps/electron/src/main/lib/agent-orchestrator.ts>)）。工具名与字段受现有 schema 约束，不能由模型选择 case/run/actor/模板/输入版本。

### 5.1 `review_read_documents`

必填 `documents:Array<ReadRequest>`，1–8 个。每项必填 `documentVersionId:string`；可选 `blockIds:string[]`、`offset>=0`、`limit:1..80`、`sheetName:string`、`fromRow/toRow>=1`、`textOffset>=0`、`textLimit:1..12000`。schema/实现 [apps/electron/src/main/lib/adapters/pi-review-ops-tools.ts:83](<../../baseline/source/apps/electron/src/main/lib/adapters/pi-review-ops-tools.ts>)。库默认 offset=0、limit=30，并把范围夹到实现上限；textLimit 默认块上限，textOffset 分页时一次只能读一个块（[apps/electron/src/main/lib/review/document-capability-library.ts:176](<../../baseline/source/apps/electron/src/main/lib/review/document-capability-library.ts>)）。

返回 `{results:[{ok:true,...readResult}|{ok:false,error}],acceptedCount,rejectedCount}`；结果含块、位置与 nextOffset。**单项失败不把整个工具标 isError**，调用方必须检查 results。读取成功记入本 run 的真实读取账；仅有材料清单或猜到 blockId 不算已读。

### 5.2 `review_inspect_document_image`

必填 `documentVersionId:string, blockId:string, question:string(1..1000)`。只加载本案当前材料对应图像块，返回 text+image 多模态 content，details 含 fileName/blockId/location/question；失败 `{error}`+isError。有效图像读取登记块级 receipt，图像内容作为审核数据处理（[apps/electron/src/main/lib/adapters/pi-review-ops-tools.ts:119](<../../baseline/source/apps/electron/src/main/lib/adapters/pi-review-ops-tools.ts>)）。图像资产检查范围、字节大小和格式签名由库核对（[apps/electron/src/main/lib/review/document-capability-library.ts:234](<../../baseline/source/apps/electron/src/main/lib/review/document-capability-library.ts>)）。

### 5.3 `review_inspect_original`

必填 `documentVersionId:string(min1)`，可选 `scope:'overview'|'page'|'all'`（默认 overview）、`page:integer>=1`。page 只能与 scope=page 同时使用；不接收路径。服务用版本 ID 找当前激活材料原件、realpath 验证案卷目录与普通文件，再调用既有视觉预览器。await 后再次核对 binding，成功且实际返回图像才记录预览凭据（[apps/electron/src/main/lib/review/review-strict-pi-tools.ts:89](<../../baseline/source/apps/electron/src/main/lib/review/review-strict-pi-tools.ts>)）。该工具以普通对象而非 defineTool 注册，所以不在 defineTool-only 的121项 schema TSV内；本节及源码保留其独立合同。all 可能触及渲染预算，失败应分页/人工核验；overview 不是整份已读，视觉预览也不自动生成文字引文。

### 5.4 `review_submit_result`

必填 `summary:string(1..6000)`；`observations?` 最多80，`checks?` 最多100；`finish?:boolean` 省略等同未要求结束。schema [apps/electron/src/main/lib/adapters/pi-review-ops-tools.ts:158](<../../baseline/source/apps/electron/src/main/lib/adapters/pi-review-ops-tools.ts>)；服务输入/返回 [apps/electron/src/main/lib/review/pi-case-review-service.ts:915](<../../baseline/source/apps/electron/src/main/lib/review/pi-case-review-service.ts>)。

| 子对象 | 字段与约束 |
| --- | --- |
| observation | subjectId、fieldKey、kind、value、sourceRefs(1..8) 必填。kind 为 text/number/date/enum/boolean/multi/object/rows/attachment，必须与模板字段和作用域一致；整案字段 subjectId 用 caseId。value 要符合该 kind 的实际值类型，number 必须有限且与引文数字一致。 |
| check | ruleId、subjectIds(最多200)、status、reason(1..2000) 必填；sourceRefs 可选，最多12。status 只能 compliant/non-compliant/awaiting-supplement/awaiting-confirmation/not-applicable；规则/目标必须在本轮有效规则与目标集合。只接收语义检查候选，确定性检查由服务重算。 |
| sourceRef | documentVersionId、blockId 必填，quote 可选最长400；事实及 compliant/non-compliant 检查需要真实精确引文，且引用当前激活版本/块。文字还必须有本轮读取 receipt 或完整原件预览，图像须真实图像块读取；未确认规则只能给 awaiting-confirmation。 |

## 9. 其余仓库接口的完整定位与修改顺序

常规 settings、workspace/session、browser/CDUT/CSLab、远程服务、共享库的宽接口不在本页重抄数百个签名。请使用 [API-REGISTRY](API-REGISTRY.md) 的**每个跟踪 TS/JS 文件**条目、顶层 export/type 定义行、实际手册链接与接受状态，再查精确 schema。`IPC-SITES.tsv` 含 invoke/send/on/handle 的静态位置，不能仅因同名常量两端出现就断言业务调用成功；动态注册与别名需继续读所属文件。

修改 review API 时，应一起核对：共享类型/通道 → preload 输入返回 → Main sender/authority 验证 → 应用服务事务与错误联合 → 真实调用方对 rejected/conflict/stale/cancel 的分支 → 既有对应测试和单文件手册。新增工具要同时改 TypeBox schema、宿主工具集合/权限门、source/read receipt 校验及收尾状态；只加模型 prompt 不会增加可信权限。本文未运行产品测试，不把存在的测试文件当本轮已通过测试。
