# CDUT Studio 合并后功能与界面验收

验收时间：2026-10-03 至 2026-10-04（跨午夜）。主项目：`CDUT-Studio`。本报告以**最新项目总文档、协作者代码和实际 Electron 界面**为依据。

## 1. 结论

**当前可用的是材料预审工作台，还没有完整的审批业务闭环，也没有达到“用户只编排模板即可使用的通用审核 Agent”。**

本轮修复后，可实际演示：新建案卷 → 导入依据/申请/证明 → 生成全部依据大纲 → 识别事项 → AI 预审 → 点击问题定位原文 → 助手解释 → 导出 MD/JSON → 重开恢复最近结果。内置案卷可以离线模拟演示，真实案卷需要可用模型。

主要差距集中在应用层和交互层：纠正识别值、替换旧材料、确认规则、人工决定、补件回复、复审/申诉、模板编辑发布、批次与独立评委操作尚未接到可用界面。不能把服务单测通过或 M1–M5 服务交付汇总等同于这些业务已经可用。

本轮 AI 路径使用**本机受控 OpenAI 兼容服务**，测试协议、上下文、失败处理、引用、隔离和界面；不证明真实模型识别准确率或政策理解能力。未配置用户的实际密钥，未调用学校系统。

## 3. 总文档与协作者功能取舍

### 3.1 当前应沿用的基座

最新 [AGENTS.md](../../AGENTS.md) 明确：CDUT Studio、**Pi 唯一内核**、Jotai、JSON/JSONL 本地存储、复用既有 IPC/全局渠道/文件能力，不引入本地数据库和另一套独立服务端。

因此审核专区继续复用全局渠道、UI 组件、Agent 执行与文件基座。审核角色和本地业务流程不要求新建团队账号系统；未来学校接入应通过已有 SchoolPort 的契约补适配器，并另验身份、权限和回执。

### 3.2 不应算作本次缺失能力的历史内容

[CLAUDE.md 的“当前裁剪状态”](../../CLAUDE.md) 列出：独立 Chat 用户模式、团队工作区 UI、积分计费 UI、远程机器人、移动端远程接入、语音输入、快速任务窗口、第三方插件宿主已裁剪。团队/同步 main 服务仍有规划和数据兼容调用方，不能按旧设计整块删除。

旧 `docs/team-workspace-file-management.md`、独立远程服务/平板文档不能作为现在必须补回的产品清单。**Agent 的普通问答能力、Skills/MCP、规划中心、会话文件面板仍有实际入口，应保留。**本轮实际验证了普通 Agent 回复、文件面板、Skills 列表与 Todo 操作。

校园 RAG、学业备考属于其他成员的原始产品职责；最新总文档没有充分证据说明它们已取消。当前“CDUT 专区”实际显示“业务功能构建中”，不应把占位页算成这两项已完成，也不由本轮重新实现。

## 6. 为什么还不能称完整闭环

### 6.1 界面与后端之间缺的连接

- Renderer 仍是 V1 三栏预审控制器，没有 V2 模板/批次/角色工作区。
- V2 IPC 只有模板列表/读取/发布、运行列表/读取/取消、V1 迁移、引导检查。缺少用户可调用的模板草稿保存、V2 运行启动、事实修正/证明绑定、业务决定、补件、申诉、评委提交等命令。
- `business-workflow.ts` 明确是纯函数，落盘由调用方负责；当前没有接通持久化命令应用层。`requestId` 也没有形成动作去重；角色/阶段权限和两级流程需要应用服务验证，不能把带有 actor/stage 字段当成验证已完成。
- `recordDecision` 目前通过/部分通过直接把 case 标为 decided，驳回也进入 awaiting-supplement；完整多阶段、事项/案卷决定需要按模板流程解释和校验，不能直接套用这组简化迁移。
- `run-service-v2.ts` 接收注入 executors；真实 Pi 执行器与用户入口仍待接线。`NullOcrPort` 如实表示不可用，没有真实扫描材料管线。

这些是本地版自身缺口，与老师暂时没有 API 无关。SchoolPort 的 Mock/离线适配器能支持演示数据来源，但不能补上上述用户操作。

### 6.2 用户已经知道方法，仍会遇到的障碍

| 角色 | 实际不合适之处 | 完成要求 |
| --- | --- | --- |
| 学生/申请人 | 日期/等级识别错了没有修改入口；修订文件只能追加，旧材料不能停用；没有补件回复和申诉；学年/分数占位影响非综测申请 | 可纠正并保留原值；替换/停用版本；按事项查看可公开反馈；补件与决定关联 |
| 老师/审核人 | “建议待确认”没有确认按钮；不能标误报、部分通过、退回或正式核定分数；零问题不能证明每条规则执行了 | 事项与案卷两层决定、处理理由、规则确认、逐项检查账本、确定计算、可恢复待办 |
| 评委/组织者 | 没有分配、回避、独立评分、缺评、同分/名额和定稿入口 | 接通已有 judging 服务与持久化，评分包/盲评界面、人工分与 AI 意见分列 |
| 模板负责人 | 只能切领域和生成大纲，不能配置字段、证据槽、条件、公式、流程和输出并试跑 | 完整模板编辑/校验/示例试跑/发布版本/导入导出；第七业务不改源码可复用 |

其他仍需处理：来源块缺原件预览；PDF/Office 经扁平文本切块，页码统一为 1，不可声称真实页坐标；XLSX 未保留 sheet/单元格结构；一个问题只使用首条规则锚点，没有多出处切换；长材料缺搜索/折叠与摘要导航；运行只有 spinner、无阶段/取消入口；审核助手线程没有用户可查的持久历史。`loadDemoCase` 失败时回退到列表第一案的逻辑也应限定为有效演示案，避免载入真实案。
