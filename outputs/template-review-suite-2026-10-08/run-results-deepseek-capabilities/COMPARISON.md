# DeepSeek 审核能力库对照记录

基线与最终复跑使用同一份合成案卷、同一模板 student-award-credit-v1@1、同一 DeepSeek Flash 渠道。最终版从干净副本运行，Agent 保持项目 Pi 审核 Agent，只增加案卷范围内的材料能力。

| 指标 | 基线 | 能力库最终版 | 变化 |
|---|---:|---:|---:|
| 耗时 | 19.38 秒 | 21.29 秒 | +9.9% |
| 已完成检查 | 6/6 | 6/6 | 相同 |
| 能力日志记为完整读取 | 0/4 | 4/4 | +4 份 |
| 输入 token（含缓存命中） | 60,865 | 56,662 | -6.9% |
| 输出 token | 3,955 | 3,901 | -1.4% |
| 输入 + 输出 token | 64,820 | 60,563 | -6.6% |
| Pi 模型查询数 | 2 | 1 | — |
| 最终版唯一工具调用数 | 基线计数不可比（旧 runner 重复计算流式增量） | 8 | — |

输入 token 按 inputTokens + cacheReadInputTokens + cacheCreationInputTokens 计算；最终版还计入按需视觉子调用的输入与缓存 token。输出 token也包含该视觉子调用。这样比较的是实际消费量，不把缓存命中当作零 token。

基线曾把规则、工作簿和团队名单的文本预注入模型上下文，因此表中 0/4 表示旧流程没有逐份材料读取记录，并不表示模型没看到这些文本；扫描证书图像则被拒绝，未能核验。能力库版本以实际读取与图像核验记录材料覆盖。

准确性方面，基线把团队名单判为“符合”，但名单明确为虚构且不代表主办方核验，证书也没有申请人 TEST-STU-03；最终版把这项转为人工确认，并指出名单与证书成员不一致。最终版还识别出同一 TEST-EVENT-02 在三个综测分项重复申报，将成员分配与去重交由负责人确认。最终版 6 项都完成了状态提交，其中 6 项待人工确认或补件，未自动确认分值。对这份刻意缺少正式依据的合成案卷，这是预期的保守结果。

速度增加 +1.91 秒；总 token 下降 6.6%。该样本显示材料覆盖和判断准确性提高、token 略降，但暂未提速；样本只有一份合成案卷，不代表所有模板。Pi runner 报告的费用不包括网关视觉子调用，因此不比较总费用。

最终运行明细与完整案卷副本见 cases/deepseek-capability-final-v6/；历史基线保留在 run-results-deepseek-baseline/。
